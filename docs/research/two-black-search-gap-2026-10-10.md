# 两区域纯黑实测与搜索范围缺口

## 明确结果

本次用户实测会话为 `20261010-111934-22c4c07e`，前两区启用精准 `#000000`，第三区禁用。规则归一化和评分没有误把第三区纳入目标。

真实结束为 `#4E5B5B / #47383B / #A1B160`，前两区 ΔE76 为 37.81 / 26.14，执行两次小拖动。这些色差很大，仅是有限已评估候选的妥协结果，不能称为足够接近、全域最优或色板无解。

留存原始色板两区分别有 254 / 30 个纯黑像素。进一步对两区黑像素中心逆解畸变和共同位姿，再用已验证 CPU 模型复读，找到多个前两区同时为 `#000000` 的连续位姿。

其中一个旋转为零的例子：

- position: `[0.021677311338362037, -0.31210069775155674]`
- scale: `0.7477669558051687`
- rotation_degrees: `0`
- 模型前两区 HEX: `#000000 / #000000`，ΔE76 均为 0。

对于本次约 499.2 像素宽高的色板，该 position 对应约右移 10.82 像素、下移 155.80 像素；这只是位姿换算，不能当作已验证鼠标动作。滚轮以支点改变位置，不能简单把平移和缩放各自直接发送。该位姿缩放在游戏 0.5 至 3 范围内。

## 为什么当前工具漏掉

控制器每轮传给搜索的 coarse grid 只有当前位置附近的 ±0.04 / ±0.02，缩放为当前 scale 的 0.99 / 1 / 1.01 / 0.9999，旋转固定。target seeds 也沿用这些尺度与角度，并非搜索整个 0.5 至 3 缩放区间。

执行过滤只允许每次不超过 5 像素的平滑拖动、单档滚轮及最多四次动作。最终选出的两次拖动累计仅约 7 像素。单档滚轮约 1% 缩放，与例子所需约 25% 缩小存在明显差距。

第一轮完成 1467 个局部路线评估；后续 pipeline 完成 coarse 244、compile 16、structural 1、macro 319、pivot 0，过滤拒绝 20 个路线。总目标规划约 11 秒即转入妥协。第二轮重放并核对既有妥协后续动作，没有继续全域精准搜索。因此不是仅把时间预算增加一点就能解决，候选尺度范围和合法执行路线也必须扩大。

## 证据边界

双区分别有黑像素一般不自动证明共同姿态可达；本局通过共同位姿实际模型复读，确实证明连续模型存在双黑解。

该证据没有证明离散滚轮、整像素鼠标和运行时输入采样能精确到达该位姿，也没有执行新游戏输入。原实测仅支持两次微拖动模型响应；不能把数学姿态标为已实机命中。

## 后续实现要求

1. 先用目标颜色的逆畸变坐标解共同位姿，覆盖游戏允许的全尺度，并按接近当前姿态及落点容忍范围筛选。
2. 将连续位姿转成有真实回读的长距离拖动、较大缩放和精细定位路线，逐步校验，不能直接复用现有微动作验证结论。
3. 精准路线未确认前保留明确的“已发现模型精准姿态但输入路线未验证”状态；不要直接把大色差候选当作完整搜索结果。
4. 在会话时间足够时优先搜索和定位精准目标；穷尽当前可用阶段后，才选择同局搜索的较优妥协，并明确显示实际色差和搜索范围。
