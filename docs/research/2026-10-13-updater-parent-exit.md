# 旧版本更新超时：父进程退出检测（2026-10-13）

桌面官方0.4.3连续两次更新到0.4.4失败。已下载并暂存全部变更文件，事务仍为 `staged`、`completed=[]`，安装器报 `parent process did not exit; installation cancelled`。未开始替换程序文件，原0.4.3保持完整。

根因不是下载、签名或安装权限。Windows进程退出后，启动器保留句柄时，`GetProcessTimes`仍能查询原创建时间。旧 `process_creation` 仅以该时间作为存活证明，`wait_parent` 因此把退出的进程判为仍存活并等待60秒后取消。真实Python子进程退出并保持 `Popen` 句柄的反例稳定复现，失败测试已在修复前记录。

修复：查询创建时间之前，以 `WaitForSingleObject(handle,0)` 检查进程对象是否已完成。已完成返回无存活身份；仍运行才比较创建时间，保留PID复用保护。异常等待状态抛出错误，不继续替换文件。

验证：

- 真实已退出且保留句柄的父进程不会阻塞；真实存活父进程仍阻塞。
- 更新安装器、恢复引导、更新事务、UI及退出相关21项回归通过。
- 修正后的冻结独立安装器以真实父PID/创建时间完成0.4.3到0.4.4差异升级，约17.97秒；测试刻意保留已退出父进程句柄。
- 最终恢复入口脚本直接运行上述独立安装器，真实隔离续装约19.86秒完成，原用户资料保留，1283个文件核对通过。入口明确等待安装器本身退出，不等重新打开的工具退出；早期入口的退出码误读和等待后代进程问题均保留失败记录，最终入口复验通过。
- 本机桌面目录在正常关闭工具后续装原已下载事务，约14.45秒完成。官方签名及1283个程序文件逐项核对，颜色、优先级、原设置和其他用户数据保留，待更新标记清除。
- 实机验证记录不依赖游戏，不消耗染色道具。

旧版本限制：0.4.3和早期0.4.4已嵌入旧安装器。补修构建不能修正已经启动的旧安装器，也不能保证它们第一次自动升级不再触发该问题。旧用户需要独立恢复入口，或关闭工具后使用完整官方包保留data覆盖程序文件。新源码的修正只会保护使用修正版安装器的更新流程。0.4.4补修沿用版本号，同版本不提示更新；独立恢复包和完整包覆盖步骤在五语发布说明中列明。
