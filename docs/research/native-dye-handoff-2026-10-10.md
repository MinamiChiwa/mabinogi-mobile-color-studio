## 1. 结论

精准染色可以采用“当局完整像素 + 原生CPU取色 + 离散输入终点搜索 + 游戏HEX反馈”的路线。无需先逐像素复刻GPU显示图，也无需先抓网络包。基础BMP已解包，但基础素材不能代替服务器重排后的当前局片段；结束局留存数据也不能当作即将开始的新局数据。

研究链条已经完成有限实机验证：恢复初始三色、横向到达非初始目标、正向单wheel到达非初始目标、负wheel/对角drag两轮混合到达目标。最后一局两次实际输入/两轮fresh规划约30.75秒，结束倒计时89秒，七份checkpoint/十四张截图/十六组backend记录独立核对通过。

这些成功目标由当前模型生成，属于有限可达控制；不是用户任意HEX盲测，不证明所有三色组合可达或搜索完备。正式Runner/UI还没有连接原生闭环，本次不修改默认产品路径、不构建或发布版本，也不自动确认染色。下一开发阶段已有足够证据从正式项目接入开始，不应再为重复已有有限结论立即消耗道具。

| 内容 | 当前结论 | 实施含义 |
| --- | --- | --- |

| 显示与取色 | Shader显示和CPU取色的运算顺序及覆盖层不同 | GPU复刻可保留为预览，不作为精准接受前置条件 |
| 输入坐标 | 本构建legacy鼠标H−y−1，连续RectTransform边界H−y | 显式用`windows_legacy_mouse_pixels`，不要修改真实鼠标坐标去重复补偿 |

| 移动门槛 | 当前有效tracker门槛0，已移动容差约.1，配置里曾见5 | 使用有效对象settings，不能误把声明默认5当实际运行值 |
| 滚轮 | 当前Windows发送约定±120的净游戏delta为±1，倍率约1.01/.99 | 一档分别重放，乘积.9999，不是精确逆操作；别混用其他computer-use滚轮符号 |
| 位姿精度 | 支点/分段不同可能改变float32终点，但颜色可相同 | 对实际提交的完整路线重新评分；相同净位移不等于相同精确终点 |
| 动画和会话 | 稳定native位姿、动画完成、纹理/几何/进程绑定必须核对 | 指针存在、旧capture或一次读数不等于有效活动会话 |

CPU核心采用实际picker的运算顺序而非显示UV公式：先`.5+position`、片段index/count、乘逆scale，再按原生顺序旋转与两轮正弦剪切。采样按像素中心与周期回绕；保存PNG为top-down，游戏数组为bottom-up。ColorPreserveRatio域为0≤p<1，p=1异常边界拒绝；Color32包含float32加.5/floor与精确半整数取偶，不能直接替换为普通round或numpy.rint。

资源预览：[四类基础图](LOCAL_RESEARCH/outputs/base_palettes/preview.png)。服务器相关指令研究用于解释当局纹理构造；没有采集网络包，没有写游戏内存、注入或远程调用游戏函数。本地搜索无需先取得网络协议；最终服务器染色结果没有验证。

## 5. 建议的数据契约

将以下契约作为服务边界，名称可沿用现有dict，不必先重写为大型框架：

| 数据 | 最少内容 | 失效/拒绝条件 |
| --- | --- | --- |
| Session | 进程创建身份、构建、活动局token、三片段像素指纹、picker/ratio、settings、几何/viewport约定 | 变局/重启/版本未知/像素变化/无活动对象 |
| Checkpoint | 同局绑定、当前pose、动画稳定、CPU/client HEX一致、两张独立截图读色/计时、时间戳 | 未稳定、读数矛盾、截图不可用、计时突变 |
| Goal | 三条规范化enabled/exact/colors/tolerance规则及指纹 | 全禁用、空启用目标、非布尔/坏HEX/非有限容差 |
| Plan | Session/Goal指纹、参考pose、计划时间/截止、完整路线/终点/逐区评分/名义耗时、诊断候选 | 换目标、参考变化、计划过期、描述符不支持、余量不足 |
| Feedback | 实测HEX/pose、target_exact、accepted、模型响应误差、停止原因、证据路径 | 已发送但receipt未知/读色失败时不得宣称当前位置或最佳已恢复 |

计划schema2必须在重验证时显式提供当前rules。HEX大小写/单个井号/外侧空格可规范化，备选色去重排序；exact模式唯一接受条件是RGB全部相等，非exact沿用CIELAB欧氏ΔE76，不是CIEDE2000。禁用区域评分为null，不能据此省略需要的实际会话/画面检查。

运行时应明确区分以下结果：

| 状态 | 含义 | 是否自动输入 |
| --- | --- | --- |
| `predicted_exact` | 合法模型路线终点每个启用区域HEX完全相等 | 仅在临近完整重验证后可提交首手势 |
| `predicted_within_tolerance` | 全部规则接受，但至少一处非精确相等 | 同上，且保留用户原容差语义 |
| `not_found_in_budget` | 有限时间/候选/当前策略未保留达标路线 | 不输入；最近未达标候选仅诊断 |
| `insufficient_time` | 工程或游戏余量不够 | 不输入 |
| `target_observed` | 真实稳定checkpoint和双帧HEX已满足用户规则 | 停止，展示结果，由用户手动确认 |
| `model_response_mismatch` | 实际位姿偏离允许的模型响应误差 | 停止，不盲目补发后缀或返程 |

“模型达标但操作不支持”“未找到”“必要颜色范围排除”可作为额外诊断原因，但不要把一般未找到显示成数学不可达。当前1467候选和每符号最多16个单wheel细化起点都只是有限覆盖；全部局部候选完成不等于全域完成。

若产品保留妥协方案功能，应另立明确的选择/定位/实测复核流程。不能把研究`nearest_diagnostic`直接当作达标候选发送；它的规则归一化rank也不应悄悄替换现有`best_result.ranking`的邻域稳定性/妥协策略。

## 6. 接入顺序与验收

| 阶段 | 范围 | 交付和验收 |
| --- | --- | --- |
| A：归档与迁移 | 将研究读取/计划/IO核心及资产放入项目边界，保持UI默认路径 | 无绝对工作区依赖，明确构建布局来源；新/旧保存局重放和规则/绑定/失效测试通过 |
| B：只读影子诊断 | 在现有Runner生命周期注入原生服务，只读当前会话/规划，不构造发送器 | 默认关闭的内部选项；新局绑定正确，原生和真实HEX一致；停局/重启/更新/缺权限均Unavailable |
| C：受限执行服务 | 从当前checkpoint规划，只提交一个首手势，实际回读后有限重规划 | 默认不替换atlas；先保留现有小drag/±1wheel策略和停止条件；模型/异常/零输入入口测试通过 |
| D：任意用户规则 | 将UI的三规则而非模型witness传给服务，接入状态/结果/日志 | enabled/exact/备选/容差、未找到和时间不足显示正确；容差接受不显示HEX精确；新增任意用户目标受限实机验收 |
| E：范围与发布 | 单/多区域、跨局、更新/DPI、预算、打包及回退 | 完整项目回归分别报告通过/跳过/失败；资产打包和干净目录运行通过；根据新增实机证据确定版本定位 |

第一轮建议只做A/B，先把只读提供器和原生规划变成可复用项目服务，并保留老路径。不是要求将研究脚本的CLI、目录命名和生成目标模式全部并入UI。正式执行新路径启动后若失去原生绑定，应停止并说明原因；不要在已操作本局后悄悄切回旧atlas并宣称当前/最佳位置仍可信。

`Runner.event`和现有UI队列可承载新服务状态，`stop`/F9和所选窗口对象继续共享。新增运行策略需明确扩展`app.build_runner`与`Runner.launch`当前仅atlas/legacy的约定及其测试；名称`native`在本报告中只是建议，当前代码还不接受。UI现有`Card.rule()`结构与规范化Goal可衔接，三语状态文案、profile兼容和运行中改目标失效应一起验收。

不要复用`Runner.submit/apply_result/reject`作为新原生服务的收尾路径。这些旧方法具有点击/套用/取消行为，本研究没有验证服务器最终结果；新流程只展示真实游戏HEX并等待用户手动确认。

## 7. 时间与输入保护

研究实际采用发现扫描起计90秒工程上限、游戏倒计时保留20秒、额外8秒动作/反馈余量；默认每轮规划最多12秒。这些是当前受限实验配置，不是“所有用户局都需要20秒”的游戏常数，也不能忽略发现扫描、初始化、OCR和checkpoint耗时。

每轮按最早工程/游戏截止计算余量，准备、候选、细化、完整终点audit和验证全部计账。返回时再检查动作+反馈是否能完成。规划参考可能在搜索超过5秒后变旧，所以输入前必须重新采集当前checkpoint/双帧；只允许缩短截止，不因单帧较大OCR延长局时。

阶段66揭示117整串OCR共同漏1、阶段67揭示大量保护回调重复完整会话读取；不能只靠模型模拟发现这些性能和读色问题。当前`planning_check`每次执行F9/焦点/窗口/截止，完整会话probe首次及每.25秒重读；输入前完整验证不受限频影响。未来性能记录应补上各阶段耗时和完整probe次数，不能把10ms成本模拟当实机测量。

标准输入描述符当前支持drag/wheel、整数客户区像素、12px内边界、drag每轴离锚点≤5px/段≤1px、至多11点、wheel±1及标准时序。plan最多4动作是研究audit上限；首次混合实机内部更严格只允许2轮/2次，第二手势必须互补。推广动作数/长drag/旋转时要重新验收，不应因模型能找到长路线就直接放宽。
