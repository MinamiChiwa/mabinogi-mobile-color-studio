# rc11 白黑黑妥协结果调查

本轮只分析用户留存记录并做本地 CPU/路线复算，没有游戏输入、进程读取或新增染色剂消耗；尚未修改生产策略。

## 本局证据

会话：`project/outputs/server-preview-0.4.3rc11/ColorStudio/data/sessions/20261012-233913-840b41cd`。目标按 1、2、3 优先级为 `#FFFFFF / #000000 / #000000`。六次输入后最后一次截图确认的颜色为 `#B59170 / #56522E / #000000`，色差约为 `44.6436 / 40.7514 / 0`。本局约 66.875 秒时由 F9/停止请求中断，并非正常完成、时间不足或搜索穷尽。最终结果中的 actual 为 null，不能拿最后确认值冒充停止瞬间的新测量。

初选预测为 `#B5916F / #56522E / #000000`，实际完整回读与之相同；后续细化只将第一色区改到 `#B59170`。本次大色差不是 HEX 误读或主要执行偏移。

前两区使用相同材质色板。第一色区像素每通道最大值为 `[255,252,231]`，双线性插值与取整不可能生成纯白。第二色区所有像素的 RGB 和至少为 3，凸组合不能让三个通道都舍入为零，因此纯黑也不可达。源像素中距第一目标最近的是 `#E7E7E7`（Delta-E 8.4961），距第二目标最近的是 `#010101`（0.2747）；这是分别的源像素结果，不能推断三取色点可同时达到这些颜色，也不证明其为连续色域的最小 Delta-E。

## 搜索与排序缺口

周期搜索的精准目标位置数量为 `[0,0,48]`。`search_periodic_targets` 的单可用目标分支只在原 scale/rotation 下枚举第三色区精准黑位置；前两区没有精准色时，缺少其近似色的联合全周期候选。执行路线搜索和细化因此从不佳的候选出发。

`priority_components` 把全部色区的满足位放在全部色差之前。因此当前 `[未中,未中,精准黑]` 在排序上胜过 `[未中,未中,接近黑]`，即使后者明显改善前两个高优先级色区。该规则与此前 Similar 模式“先满足容差再细化”测试有关，不能未经分析就将所有模式统一改成误差交错排序。

## 离线反例与限制

使用 `#E7E7E7` 只生成临时候选，再用原始白黑黑目标重新 CPU 评分，约 1.047 秒获得 `#E7E7E7 / #473719 / #000000`，Delta-E 为 `8.4961 / 32.1727 / 0`。这说明原候选不是数学色域上已知的最佳妥协；临时目标没有用于生产验收。

通过现有输入编译器编译并完整重放后，其中一条七动作路线预测为 `#E8D9D2 / #4A4323 / #040404`，Delta-E `14.0736 / 34.8769 / 1.0925`。描述符输入时间合计约 3.81 秒，不含实际输入前检查、settle、回读与纠偏；尚未实机验证。现有原始优先级质量评分拒绝它，因为第三色区失去精准黑。对这三条编译路线额外枚举 ±8 像素的整数平移，没有找回第三色区精准黑，不能据此声称不可恢复。
