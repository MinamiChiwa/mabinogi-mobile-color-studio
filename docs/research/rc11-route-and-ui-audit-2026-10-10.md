# rc10 两次中断与 UI 点击审计

日期：2026-10-10。修正候选为 0.4.0rc11，策略 `native-measured-continuation-v9`。

## 实际失败原因

rc10 会话 `20261010-165104-d8aa6fdc` 和 `20261010-165313-7309f328` 都启用了三区精准纯黑。第一次搜索各生成了低色差妥协路线；两局只执行第一条拖动与第二条旋转。旋转之后角度残差分别为约 0.00007915°、0.00107956°。控制器把妥协路线的残差当作重新全局搜索的触发条件，再耗费约 23.3 秒、23.6 秒，随后整条路线的时间预算不足而不输入。最终保留的是仍远离黑色的中间姿态，不能归因于没有暗色路线。

从第二步实际姿态继续重放第一次规划的剩余动作，终点仍为低色差暗色，最大 ΔE76 约 1.50、3.46。因此重新进行全周期规划在这两次残差下没有必要。

原生稳定检查约 0.61–0.66 秒，完整观察约 2.38–9.28 秒。慢局截图里的 `#F197AE` 需要多个 OCR 变体和逐字识别，单帧总计 19 个 OCR 子进程调用。初始两帧和输入前两帧的整张颜色卡像素都完全相同，重复识别占用了额外时间。

UI 故障已在真实 Windows Tk 中复现：任务虽已结束、busy 为 false 且没有 grab，置顶的结果浮窗仍盖在主窗口上。多个按钮中心的实际命中对象是浮窗的子控件，表现为按钮失效或功能错位。旧的“大 JSON 阻塞”解释没有证据支撑。另确认了返回原宽度后的陈旧重排任务、缩放后未更新的内嵌画布宽度，以及重复计算滚动条宽度的问题。

## 修正行为

- 不再因操作姿态残差的大小停止、丢弃或重搜一条正在执行的路线。后续每个动作都从实际游戏回读的姿态重新计算预测；剩余路线端点重新评分并记录。精准目标仍以实际 HEX 接受，不因预测或近色放宽规则。
- 中间稳定原生回读的残差不触发额外截图/OCR。提前精准命中和路线终点仍做两张新截图核对。用户停止、窗口/会话身份改变、未知输入结果和真实时间边界依然分别检查。
- 截图识别缓存由每个 IO 会话单独持有。只有整张颜色卡 RGB 像素和尺寸完全一致，且已有截图识别的六位 HEX 与色块校验通过，才复用识别值。每帧仍独立截取并重新测量布局，仍与当前原生 HEX 比较；原生补值不进入缓存。像素变化、缺字或非法值继续原识别，最多保留 96 个条目。
- 原生任务 finished 后收起置顶浮窗，结果保留主界面及历史；下一轮 begin 重新打开。修复陈旧布局重排、画布缩放和滚动条尺寸计算。

## 旋转模型证据与限制

原游戏标量 SignedAngle 与内嵌 acos 在两条旋转路径共 1056 对输入向量上与当前模型逐位一致。没有找到可合理替换当前算术的固定校正常数。AVX/FMA acos 分支因模拟器不支持一条指令尚未核验。

分别枚举 12951 组漏采点假设，可以用原有算术得到两局实际角度；但多个采样序列产生相同角度，没有一组同时严格复现所有位置浮点数。因此帧采样差异是有支持的解释，不是已经恢复的实际游戏采样序列。桌面鼠标写入及 Win32 读到位置并不能证明 Unity 接受了每个点。

目前不能承诺实机预测零误差。此次把残差用于更新实际状态，不用放宽误差门槛掩盖差异，也不因差异中止路线。进一步消除采样残差需要游戏可见样本序列或经过验证的输入采样保证；保存的端点不足以提供这些证据。

## 回放与 UI 验证

使用两次实际保存路线、第二动作真实姿态和保守的读取/输入耗时进行回放，两条路线均只进行一次规划并完成八个模拟动作：

| 保存会话 | 模拟终点 | 最大 ΔE76 | 带实际成本的模拟耗时 |
|---|---|---:|---:|
| 165104 | `#020202 / #020003 / #030003` | 1.50 | 57.78 秒 |
| 165313 | `#080608 / #0B0B0E / #060403` | 3.46 | 45.98 秒 |

这包括录得的旋转残差，但剩余动作仍为条件模型模拟，不是新的实机运行。模拟耗时尚未扣除缓存带来的节省。

保存截图重读中，慢局的输入前双帧复核降到约 1.22 秒（含保存 PNG 与计时识别），HEX 一致，整卡重复 OCR 为零。这是保存图像性能测试，未测新的真实游戏截图链路耗时。

真实 Tk 在 100% 和 150% 控件缩放下验证七个主控件命中、颜色回调、启用切换、保存、历史、无 grab、下一局重开。旧浮窗行为的反向测试仍会在两种缩放下失败。此处没有修改桌面 DPI，也没有操作游戏。

完整套件 1118 项：1100 通过、18 个可选本地资料检查跳过、0 失败。发布包 11 个关键模块与源码逐项核对，生产指纹为 `bcb26551656cf8d2c9393f36bf99ada50c123663528968d9063552200f540745`。完整测试日志和构建身份保存在 `outputs/native-integration/verification/rc10-runtime-audit`，最终记录为 `rc11-verified-full-tests.log`。

本轮未开新染色局、未读取新的游戏会话、未发送游戏鼠标输入、未消耗道具。候选是路线继续执行、截图性能和界面交互修正，不是所有三黑精准率或采样零误差保证。
