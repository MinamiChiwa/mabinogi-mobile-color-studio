## 原因与修正

旧 `_cursor_proof` 把工具进程的 `GetCursorPos → ScreenToClient` 与 HWND 专属 `PhysicalToLogicalPointForPerMonitorDPI → ScreenToClient` 强制比较。Windows API 约定不保证调用进程/线程 DPI 环境下这两种读取器路线数值相同；这个差异不能证明独立测量的四角或完整整数轴地图已经变了。它在普通窗口中因光标从外面进入游戏而触发，先于原生姿态/色码回读，阻止了本来应当依据实际状态继续校正的流程。

rc16 将此读取器比较作为诊断项：匹配、不匹配、光标移动/在窗口外、可选读取器 API 不可用分别记录，不再作为有效轴地图的拒绝条件。保留所有进程、HWND、版本、输入分支、viewport、物理四角、完整坐标表、重复读、单调/可分离、指纹、实际窗口变动、F9、焦点与未知输入完成校验。原生 checkpoint/CPU/HEX 和实际动作后重放仍判断当前结果；不自动切换坐标模式，不加容差掩盖目标差异。

读取器 raw physical/query/converted client 坐标、差值与状态写入独立诊断，置于会话绑定之外，避免光标移动本身改变窗口指纹。另记录受支持 UnityPlayer 原生 mouse cache 的重复读结果，标注 `freshness_verified=false`，不会把两次值相同当作新帧/真实事件证明，更不会据它选择输入模式。预检及 checkpoint 都保存诊断；下一次实际动作后的原生姿态/色码不再被这个读取器比较阻断。

## 验证范围

实际远端 175% 完整表作为固定回归，光标比较不一致时仍可验证原表且不修改它；真实最大化尺寸在控制 API 下复现同一诊断状态。可选读取器失败与取消/截止分开：API 失败记未知，F9 和截止继续硬约束。原生鼠标缓存的未知版本、值变动、未证明新鲜度与 F9 均有测试。

这些检查验证误停止条件的修正，不证明本次远端拖动的真实游戏响应，也不证明新的 175% 精准成功。上传资料缺少动作后的状态，需新版本实际回读。证据目录：`outputs/native-integration/verification/rc16-window-experiments`。

首次完整回归 1303 项只有一项桌面浮窗像素测试失败：独立的绿色测试窗口映射之后尚未进入桌面合成，前置基准图采到了其他窗口，失败在浮窗创建之前。测试现先用非激活置顶显示及 DWM 合成确认已知绿色像素，再进行浮窗像素不变、命中和焦点检查；不放宽后续断言。相关 18 项实际 Tk 与策略测试复测全部通过，随后重跑全套。

## 最终交付验证

修复后的完整套件 1303 项：1285 通过，18 个可选文件检查跳过，零失败，391.948 秒。包内 110 个模块与源码字节码一致；包内直接执行了远端 175% 坐标表、最大化尺寸映射、截图复读、原生鼠标缓存诊断和四种缩放控制器验证。rc16 包内普通界面只读预检通过，输入为零。
