# 高 DPI 坐标测量与整数输入映射

用户上传的 `native-preparation.json` 和 `native-preflight.json` 表明 rc14 已正确定位到 `C:/Game/MabinogiMobile_TW/appdata`，游戏、metadata、UnityPlayer 哈希均匹配。新的错误为窗口测量阶段的 `Physical client extent mismatch`，发送输入仍为零。旧测量将 `GetClientRect` 的客户坐标尺寸，强制与 `ClientToScreen` 后的屏幕像素尺寸相等；高 DPI 环境下这两组量可以不同，因此还没进入 Unity 尺寸映射就失败，且丢失了实际数值。

## 测量修正

物理客户端尺寸由目标窗口 DPI 上下文中的客户矩形，经 `ClientToScreen` 和 HWND 专属 `LogicalToPhysicalPointForPerMonitorDPI` 转换四角后得到。原始 API 客户矩形、目标窗口上下文的客户矩形、物理四角、DPI awareness 以及反向 `PhysicalToLogicalPointForPerMonitorDPI / ScreenToClient` 往返检查分别保留。原始 reader API 矩形可以是逻辑 1280 或物理 1920，都不再直接当作目标客户坐标。测量失败也保存部分值；重复读回确保窗口未移动。截图和实际鼠标定位的 `Game.geometry` 同步使用该转换链，避免预检通过后仍按逻辑 1280 截错物理 1920 的图。

只读预检 CLI 保留自动选中窗口 HWND，也允许明确 `--pid / --hwnd`。支持版本的 Unity Screen HWND 原始字段双读后，与选中窗口绑定，避免把辅助窗口误当主窗口。

## 输入模型

当物理客户端和游戏渲染尺寸不同，逐个物理整数像素通过 Windows `PhysicalToLogicalPointForPerMonitorDPI` 和目标 DPI 上下文下的 `ScreenToClient`，得到游戏客户坐标。每轴在三条不同固定坐标线上验证可分离，完整轴重复读回，窗口四角在前后复核，缓存记录带完整内容指纹；每次使用核对绑定和坐标样本。

这些表描述 125%、150%、175%、200% 等缩放时的实际整数阶梯，不假设 DPI 除法的舍入方式。原生鼠标转换仍按 recovered float32 viewport 运算、floor、H−y−1 处理，再由原生色板边界变换到 UI 本地坐标。截图的连续色板边界投影与整数鼠标格点是不同路径。映射写入 checkpoint、上下文、路线种子绑定及所有重放；细化缓存保留每个实际接受的原生事件，不能把一串旋转简化成一个总角度。

精准 HEX 规则、实际回读、截图独立核对、返程预算和 F9 行为不变。完整映射创建后继续重复读窗口和 Unity Screen，防止在收集过程中移动窗口却发布过期地图。给导出地图添加色板/viewport 字段时重新生成摘要，不混用原始地图摘要。

缩放平台上相邻的两个物理像素可能映射到同一个游戏像素。微小旋转现在从实际表中选择下一个不同的原生像素，避免 175% 缩放时一像素弧线被完全折叠，导致局部搜索没有任何旋转候选。

## 验证与边界

新增坐标、窗口、上下文和控制器测试覆盖非 1:1 尺寸、整数阶梯、负坐标、取整顺序、变动/伪造地图和焦点上下文恢复。控制器在四种缩放上使用独立逻辑坐标路线重放作为实际 IO oracle，对比模型预测与回读。

窗口 reader 的两种原始 API 情况（原始矩形逻辑 1280×960、或原始矩形物理 1920×1440）都通过相同的目标 HWND 转换链测得物理 1920×1440，反向四角转换也核对通过。原始 reader API 量只作为诊断，不参与猜测物理大小。

首次完整回归 1291 项暴露三类问题：新增三条错误提示缺英文翻译；旧 borderless 测试未模拟新增目标 DPI 上下文和物理转换 API；部分返程故障测试把临界 3 秒真实搜索与后续故障注入绑在一起，在负载下可能没有开始试探。文案和模拟接口已修正；部分返程测试改为完整重审固定的受保护两手势候选，独立覆盖故障恢复，真实搜索/期限仍由另几项留存数据测试验证。相关 33 项复测全部通过，随后重新执行全套回归。
