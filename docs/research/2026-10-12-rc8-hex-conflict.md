## 已复现的原因

第二局已正常启动搜索并执行三次输入，30.438 秒后停止。异常为 `VisualNotReady: Screenshot and checkpoint HEX disagree`，观察重试三次。停止时工程截止仍剩约 80 秒，原始失败截图显示倒计时 95 秒；此次不属于 rc7 的 5 秒新鲜度误停。

末端与三次观察 checkpoint 的姿态一致，CPU 模型与客户端 HEX 均为 `#F27233 / #EAD310 / #72514A`，最大浮点通道误差 5.96e-8。实际截图印出的第三色也是 `#72514A`。原生 glyph 模板不能明确识别，转到旧 `vision.read_codes` 单次 OCR 路径，稳定误读成 `#725148`。A/8 只有蓝通道差 2，二者均可能通过色块距离门槛。重新截图并走同一个 OCR 处理路径会重复同一个错误；旧帧 JSON 在 merge 抛错前尚未保存，因此原报告只留下通用冲突错误。

三张真实失败图离线复读均复现上述错误。已有截图后端的独立文字读取器使用更完整裁剪、不同阈值和放大处理，对每张图均取得两次一致的 `#72514A`，没有传入预期字符，也没有从 RGB 推导 HEX。

第一局 `20261012-214752-4e3b47bb` 的结局则是用户 F9：七次输入后已经得到并通过双帧复核的 `#FFFFFF / #FFFFFF / #E3E2D5`，随后在该位置继续计算细化路线。该局不是本次三次 OCR 冲突退出。后续停止使保存结果的当前确认状态失效，不把旧截图冒充停止后的当前状态。

## rc9 修正

原生帧收集发现非空截图色码与当前同局 checkpoint 冲突时，只对冲突色卡追加独立多阈值文字读取。读取器只获得图像、色卡范围、截止和停止回调，预期 HEX 不进入识别器。独立文字仍须通过原生路径原有 ≤3 色块距离核对；没有扩大原生色块容差或精准色差阈值。通常正常匹配的卡片不付这次额外 OCR 成本。

已经证明有问题的整卡像素缓存立即清除。只有独立文字与 checkpoint 一致且色块核对通过时，才保存确认后的整卡缓存，后续独立截图仍测量实际布局、区域数和整卡像素。文字缺读、仍然冲突或色块差距过大时不会把预期色码填为截图成功。

冲突的原始色码、重新读取的文字、阈值、色块距离及结果另存到 `.decoded.json`，即使未能通过复核也保留证据；随后正常帧 JSON 明确记录是否为独立文字复读。F9、实际会话截止及进程/窗口/几何检查继续有效。慢解码后的状态核对沿用 rc8 修复，未重新引入纯截图年龄阻断。
