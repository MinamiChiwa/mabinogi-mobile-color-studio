# 双区域染色板适配

用户提供的诊断档案中，最新两局完成了进程、模块、窗口与坐标预检，然后在 `CurrentBuildBackend.probe()` 的固定三块布局检查退出。两局异常均为 `Only three-fragment layout validated`，输入次数为零，未留下双区色板像素或初始截图。因此日志证明实际数量不等于三；具体双区域由用户观察确认，本报告不虚构一次双区游戏成功记录。

## 实现

`dye_regions.py` 统一支持实际 2/3 区数量。真实区域数由完整色板数据取得，与用户开启几个匹配目标分开。碎片、取色点、client HEX、视觉卡片、marker 与内部规则数量一致；声明数量矛盾、读取途中列表变化和会话切换均拒绝。

底层 float32 picker 算术原已接受 count 参数；调用链现在使用真实数量。双区横向中心为 .25/.75，三区保持1/6、1/2、5/6。RGB 通道三、矩阵维度、两张独立截图和重试次数仍保持原含义。区域不能按纹理资源或像素哈希去重。

评分、目标种子、联合周期搜索、输入编译、反向规划和保护返回均使用真实布局。Exact 仍只接受完全相同六位 HEX，Similar 仍按各区容差。不存在的第三区域不参与优先级和综合色差。

原生视觉识别以绑定的实际 count 为约束，三区截图缺卡不会降级为双区。图像备用入口自动识别双区时要求完整方形色板四边及两卡布局证据；模糊画面停止。图像 atlas 材质掩码、周期图、旋转缩放、执行回读和单目标分支亦保持两项，不伪造第三个 marker 或色码。

主界面继续保存三份配置。绑定双区局后，第三区域灰显并标注本局不可用，不修改其启用变量、目标色或优先级。返回三区局恢复可用状态。终端结果和历史只记录真实区域；若仅启用不存在的第三区域，不构造输入执行器，并提示启用区域1或2。

## 验证边界

新增模拟 MMList 读取测试、254×254 RGB 渐变双碎片和独立预期 HEX、生产搜索/控制器/恢复回放，以及使用真实字形资源生成的双卡截图。双区客户 CPU 色值的一致性用模型和模拟客户内存验证，没有新的游戏局或染色道具消耗。

旧三区域记录及输入、DPI、严格读色保护继续回归。具体计数以本次最终测试 JSON 为准。双区域实机色板导出与真实输入结果仍需用户在新版本中测试，预检或离线模拟不构成实际精准率保证。

最终冻结发布回归：536项，535通过、1项私有OCR档案跳过，零失败/错误；执行182.402秒，入口总耗时183.329秒。独立审查发现的双区浮窗越界已补专门失败到通过回归并修复，最终限定范围没有新增重要问题。
