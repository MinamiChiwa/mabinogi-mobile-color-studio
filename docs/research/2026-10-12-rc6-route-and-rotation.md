# rc6 精准寻色与旋转误差调查

用户记录：`20261012-201059-c3e0e8a5`，三个区域精准纯白，优先级 1、2、3。记录来自本机台服，客户区 788×888、色板约 433×433、DPI 96。本轮只使用已保存的数据，未发送游戏输入或消耗染色剂。

## 已确认的失败链

1. 周期颜色搜索耗时 0.672 秒，找到 32 个近似联合目标，未在有限候选池里找到三白。路线编译和输入细化耗时 23.438 秒，选中六手势路线，预测 `#FFFFFF / #FFFFFF / #E1E6E2`，第三色 ΔE 9.70765。
2. 第一步旋转预计 −89.999832°，实际 −86.151840°，相差 3.847992°。光标记录匹配所有指定桌面坐标，实际色板 CPU 取色与客户端浮点颜色最大通道误差为 5.96e−8。这不是把错误色板读成另一张图的证据。
3. 从实测位置直接重放原后五步，预测变为 `#9C89A4 / #AEAEAE / #AABCD6`。控制器因此把当前位置 `#A8ACA3 / #9C9DA1 / #E3C465` 当作较好中间结果，停止原路线，进入该位置的局部细化。
4. 后续仅执行一次小拖动，第一优先区 ΔE 改善，而另两区变差。随后用户 F9 停止；并非游戏倒计时耗尽，也不是已经执行六步仍无法得到规划结果。

旧版严格“小于”后缀比较和 rc6 的“小于等于”比较都能复现本次中断；撤销等号并不能解决这局。rc4 保存的另两次旋转误差分别约 0.000092°、0.001007°，因此旧局不一定触发这个缺陷。不同局的色板、取色点和窗口也不同，不能以结果不同直接判定搜索算法退化。

采集基线的总时间 23.266 秒包含等待进入色板。色板第一次出现到基线采集完成约 0.813 秒，不应把总基线时间全部算为活动染色局的读取延迟。

## 大角度误差的采样机制

游戏旋转规则不仅计算角度，还比较半径变化：当 `abs(angle / 200) <= abs(radius_change)` 时，本次角度不生效。现有 90° 输入有 24 个弧段，首段约 3.8484°；直线伸出转入圆弧的第 8 个路径点只停留 18 毫秒。

对原始输入模拟漏掉第 8 点，既发生半径增长又发生角度变化，首个弧段被过滤。得到 −86.151405°，与实际 −86.151840° 仅差 0.000435°；位置最大差 1.13e−6。模拟 20 FPS 下多种帧相位的真实发送时序，旧路径可丢失约 3.85°或 7.59°。

这是强证据支持的误差机制，但日志没有游戏逐帧接受点，因此尚不能唯一恢复真实漏采序列。未用固定角度倍率拟合，也未扩大精准 HEX 阈值。此前解包标量 SignedAngle/acos 的逐位比对也未发现能够解释约 4°误差的算术差异。

## 修正

- 分组旋转在径向路径与圆弧的交界添加四个相同点，额外停留 72 毫秒，使该坐标总驻留约 90 毫秒。真实发送、预算、条件重放使用同一描述符。旧稠密路径保留用于历史对照。
- 原生控制器在偏差使剩余路线明显劣于原目标时，使用实测姿态校正原中间位置和原最终位置，再对完整剩余输入路线评分、审计及预算检查。校正沿用本局已有色板和目标，中途校正约两秒、终点校正约三秒计算，不重新扫描色板或启动全局寻色。校正未找到改善时保留原剩余路线；不以偏差后的错误预测宣布原目标结束。校正分配扣除具体的剩余执行及重试返回成本；候选审计也计入校正预算，原后缀在计算后重新核对是否仍可执行。
- 校正阶段优先恢复已选终点的联合颜色，而不是在短时预算内再次求解玩家的全局目标。否则即使已有两白方案，也会继续尝试三白，导致末端纠偏停在 `#FFFFFF / #FEFEFE / #E1E6E2`。内部恢复规则不修改玩家设置；生成的每条候选均重新按玩家原规则评分并完整审计。因此两个纯白加近似白仍被报告为妥协，不会变成“三白精准成功”。最后一步无后缀时同样执行目标纠偏。
- 原有实测较好落点保留仍适用于正常路线与独立局部细化，不把预测颜色当作精准成功。
- 另一次启动失败记录 `20261012-200638-c427c298` 中 Win32 窗口为 −32000、客户区为零，属于最小化状态。启动顺序改为先恢复/激活所选窗口，再读取几何；只读预检本身仍不主动激活窗口。

## 验证与结论边界

新增不依赖缺失私有资料的 rc6 最小回归样本。完整控制器注入实测首步偏差，后续输入按条件模型响应：修正前停在 `#A8ACA3 / #9C9DA1 / #E3C465`；修正后恢复两个精准纯白、第三 ΔE≤10 的联合目标，完成最终双帧颜色复核。此处的后续动作与截图由文件模拟 IO 提供，不能当作新实机染色结果。

新增 20 FPS 多相位输入检查、首步 F9 检查、最后一步偏差校正检查和局部 CPU 截止检查。末端偏差校正原先可稳定复现第二色 `#FEFEFE`，改为恢复已选联合颜色后连续三次通过两色 `#FFFFFF` 断言。禁用区域保持禁用，相似色验收仍使用玩家原容差，未扩大精准阈值。

最终关联专项 93 项全部通过（32.684 秒），包括真实记录的首步/末端偏差回放、两区完整控制器、原较好中间结果保留、完整精准后缀、末端截图、125%～200% DPI、最小化窗口恢复和连续重试。旧后缀测试原来固定要求两手势，但本次修改前后相同算法都可生成三手势，因此改为核对实际发送完整选择路线、末端颜色和截图，而非固定路线长度。旧两区恢复用例现在可能由目标校正直接得到原预期颜色，改为验证实际颜色、最佳状态及截图，不强制使用旧恢复分支。

最终 quick（不含桌面检查）：697 项选择，683 通过、14 项整体跳过、0 失败/错误；99.780 秒执行，106.677 秒总耗时。跳过事件 19 次还包括 5 个子测试。补回两个本地历史样本后，之前多项跳过的控制器/DPI 检查实际运行。仍有未分发样本和五项桌面检查没有参与；不声明完整 release 验收。

本局没有证明三白无解，也没有证明连续空间全覆盖。当前可确认的主要质量问题是执行偏差后原目标被提前抛弃。72 毫秒停留能通过有限采样模拟，但低帧率、掉帧和游戏采样序列仍须实机观察；没有宣称旋转误差已经绝对归零。23 秒初始路线优化仍是已测性能成本，未以缩减搜索覆盖冒充无损提速。
