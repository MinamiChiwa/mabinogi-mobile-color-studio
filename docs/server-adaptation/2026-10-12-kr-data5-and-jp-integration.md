准备时完整检查约 4 GB，耗时约 15–17 秒，主要是读取约 15 秒及搜索约 0.85 秒。准备后“等待进入染色”本身正常；进入后新活动实例的全覆盖与唯一性识别也可能耗时十多秒。未以跳过唯一性检查来消除等待。本次区分等待和识别提示，让玩家了解当前阶段。

启动按钮与 F8 虽传入 `activate=True`，精准服务此前没有消费该参数，首次回读可能在游戏失焦时停止。本次在准备和构建检查通过后、等待色板前激活已经绑定的游戏窗口；玩家运行中切换焦点仍停止输入。失焦、窗口运行中移动/缩放、激活失败分别显示原因。不会将这些停止描述为固定分辨率不支持。

离线重读初始与最后动作截图，均为 1376×990，三个色码与上传记录完全一致。证据为开发目录 `project/outputs/kr-data5-audit-20261012/saved-frame-recheck.json`。未运行游戏输入。此证据支持该尺寸流程及韩服操作复用，不证明三白成功或所有环境全部验收。

## 台、韩、日统一入口

普通主窗口的游戏窗口选项旁增加台服、韩服、日服选择。选择自动保存，检测按所选服务器过滤；切换时清除旧窗口与选择框。窗口选择框保持单实例，旧服务器回调不能写回窗口。运行期间不能改绑。精准与截图模式均沿用相同窗口定位选择。

默认寻色为精准寻色，保留用户此前主动保存的策略。共用规划、拖动、滚轮、旋转、重试、实际色码复核及浮窗。使用普通主窗口即可开始，不要求单独只读预检。旧韩服验证启动器仅保留兼容，当前 UI 选择优先。

服务器或标题不决定静态地址，精准服务仍按三个文件精确指纹核对注册适配器；选择不匹配时不给其他服授权输入。日服使用自身 palette/input/cache RVA 与未初始化标记，Unity 读取层指纹一致。候选元数据 JSON 不授权输入，修改注册对象或未知构建仍拒绝。诊断中的 `input_verified` 不因 UI 选择而改为 true。

日服基础依据为 `project/docs/server-adaptation/2026-10-12-jp-readonly-report.md` 及对应独立候选：58 类字段、核心 57 方法和 Unity 指纹复用。已重验留存候选 20 项；日服活跃色板、区域布局、实际输入响应与重试仍待实机记录。本轮未另跑日服预检，未消耗道具。完成的是共用主流程接入，不以韩服成功冒称日服实测成功。
