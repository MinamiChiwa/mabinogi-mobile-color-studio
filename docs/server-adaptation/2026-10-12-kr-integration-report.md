# 韩服生产流程接入与验证版交付

依据登录前报告、候选构建指纹和用户要求，将韩服的完整搜索/操作流程接入供实测，不把静态一致性误记为实机验收。

当前版本 0.4.2rc12 包含 rc11 的无损计算提速及 rc10 连续重试缩小。已统一 palette class 的初读与复读 RVA、未初始化 marker、MMInputSystem class RVA、legacy getter cache，以及指纹独立绑定的共享 Unity layout。TouchArea 管理包装允许经过结构比对的两服布局，仍核对运行时类名、字段偏移、对象链与重复读数。扫描函数的独立入口也选择适配器，不再硬编码台服 class。

完整 GameAssembly、metadata、UnityPlayer 指纹是选择依据。韩服 adapter 继续记录 `diagnostic_only/input_verified=false`，专用 `Korean-validation.cmd` 以 `--validate-korean-build` 显式允许确切已研究韩服构建使用现有完整输入边界。该权限仅为用户授权的验证流程，不持久保存、不允许未知/修改构建、不从 JSON 候选提升权限。普通启动可完成只读预检，但不会自行对未验收的韩服发送输入。直接输入边界再次检查权限，保持 F9、焦点、DPI/窗口、会话、后端、姿态及实际色码核验。

拖动、正反滚轮、旋转、连续缩小、F7 重试与结果回读均沿用同一现有控制器；没有为韩服新增搜索时限或改变模型。共享算法的静态依据、57 个核心方法和58类/4包装一致性的局限继续以原报告为准，活跃色板上的参数仍由真实对象读取和检查。

## 下一步

使用包内 `Korean-preflight.cmd` 先完成只读检查，随后由测试者通过 `Korean-validation.cmd` 开启完整工具。需可登录客户端验证2/3区域真实色板、CPU模型和HEX、拖动/正反滚轮/旋转、重试及回读。准备脚本及工具就绪后才进入有限道具局，不自动确认染色。

新服务器相同完整指纹自动复用同一adapter；新GameAssembly/metadata重新离线发现并确认结构，新UnityPlayer独立确认原生布局。只在准备阶段选择布局，后续搜索不反复反编译或扫描DLL。能力依据实测逐步提升；后续正式发布仍需韩服实测及签名更新条件。
