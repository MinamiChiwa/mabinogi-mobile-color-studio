## 离线证据与边界

- 沿用先前 metadata v31 / PE 结构解析流程；染色与输入类入口均要求唯一类型标记及该类自身方法的引用证据。鼠标缓存由 `UnityEngine.Input.get_mousePosition_Injected` 指令引用恢复。
- 比较 61 个相关类。字段类型中泛型参数编号归一化后，各比较类的字段签名及偏移一致。`MMList` 的父类型文本存在泛型参数编号差异，不能据此声称原始字符串全部相同。
- 染色实例、动作控制、手势识别、色板采样及扭曲五个核心类的父类和字段一致，57 个核心方法的归一化指令序列一致。归一化屏蔽重定位目标，不能证明所有辅助函数行为完全等价。
- 生成 UI Slot 构造和染色弹窗的部分方法存在指令变化，不把它们算作一致；本工具不自动确认套用染色。
- 完整私有静态比较记录 SHA-256：`8019a8e0ab4cf4dc163659db88bd934d8752b36e0b5a9aaf47fb4f497650f1ab`。游戏二进制和反汇编记录不入库、不分发。

## 接入方式

新增 `kr-20261016-static-candidate`，保留旧韩服构建。三文件指纹共同选择适配器；韩服服务器选择允许这两个明确登记的构建，其他服务器、未知构建及被改动的布局仍拒绝。只读预检和旧韩服验证启动参数也按同一服务器构建族选择，避免主 UI 能识别而预检仍拒绝。

新增构建维持 `diagnostic_only`，不宣称 `input_verified`。用户显式选择韩服后，可按已有韩服测试路径进行采集和输入验证；实际对象类名、字段、输入分支、getter、窗口与绑定检查仍执行。直接构造输入适配器不能跳过能力校验。

本轮尚无新构建运行进程、只读预检或真实色板验证结果。离线适配和回归通过不等于韩服实机验收完成。下一步先在普通界面只读预检，再由用户授权验证真实色板；不应为版本识别重复消耗染色剂。
