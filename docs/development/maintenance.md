# 仓库维护与退役规则

更新：2026-10-31。

## 当前目录

- `work/studio/` 保存当前程序、构建与仍受支持的诊断入口；Qt Quick 界面在 `qt_ui/`。
- `tests/` 保存现有离线行为测试，运行命令见 [测试指南](../../TESTING.md)。
- `docs/development/` 保存当前开发步骤；`docs/research/`、`docs/server-adaptation/` 的日期报告和正式发行说明保留作历史证据，不作为当前命令入口。
- 构建包、截图、会话、个人设置及签名私钥保留在本地，不进 Git。

## 已退役内容

2026-10-25 起，旧分步计划、独立实验副本及重复验收流水账陆续退出当前树。2026-10-30 的 Qt 迁移移除了 CustomTkinter 界面和 Tk 研究查看器，依赖中不再包含 `customtkinter`；旧测试集和 `run_tests.py` 已被当前 `tests/` 中的行为测试取代。自动更新改为签名清单与 blob，旧离线导入入口退役。

2026-10-31 核对 app、构建、更新助手、现有测试与启动脚本的依赖后，移出 34 个未接入这些入口的旧 atlas 适配器、离线 native 原型和研究审查工具；另移出源码目录中 37 份过时状态、计划与实验报告。每移走一个 Python 模块都运行完整离线测试，失败则恢复原文件并停止后续清理。没有删除测试或修改保留模块的实现。

扫描性能工具 `native_live/benchmark_dye_scan.py`、窗口检查脚本及三语 `WINDOW_CHECK.*.md` 继续保留。旧文档与模块可通过清理前提交 `278d725` 的 Git 历史恢复，例如：

```powershell
git show 278d725:work/studio/PROJECT_STATUS.md
git show 278d725:work/studio/atlas_live_adapter.py
```

本机已将退役文件及可重新生成的 `build/`、`build-updater/`、`bundle/` 和 spec 副本移至本地归档目录（由 Git 忽略），并保留逐文件校验、原路径及撤回记录；不将机器路径或生成物加入 Git。移动不释放空间，旧正式包、更新基线、用户记录和签名材料完整保留。

## 后续清理

2026-11-05 将根目录的七个诊断启动文件集中到 `scripts/diagnostics/`，修正相对源码、环境路径，新诊断输出统一进入 `runtime/diagnostics/`。日常开发仍从根目录 `run_studio.bat` 启动。

本机 0.4.10 发布目录仅保留 `assets-final/`、`build-final/`、`evidence/` 和导览；原测试副本、上传回执和一次性脚本分别归入 evidence 下的 validation、publish、historical-tools。已发布 ZIP、签名与清单保持原字节，运行副本及其会话保留原位。根目录增加本地快捷方式直达正式包、程序和日志。没有删除会话或发布基线。

截图模式四项测试发现默认会话清理实际只保留三份，导致第一项完整记录缺失。按用户要求，修复后仅按数量保留最近 10 次完成会话，不设 30 天保留期；活跃和近五分钟写入的会话暂不清理；明确指定的容量维护策略保持独立。已缺失的第一项日志不能重建为完整实测证据。

清理前先核对导入、动态调用、QML 回调、命令行入口和外部消费者，不以文件名或修改日期判断死代码。生产源码变动后执行对应行为测试；文档变动检查链接和表述。只清理已确认可再生成或已退役的内容，无法确认的文件继续保留。

移出源码会改变开发树的 source fingerprint；已有发布包仍对应原构建提交。检查历史包时须使用对应版本源码，不能用清理后的源码指纹把原包误判为损坏。本轮未重新构建或覆盖 0.4.10 资产；离线测试也不代表新增游戏内验收。

本机在归档后又按用户明确指令删除了确认无用的退役副本、失效环境、候选包及测试程序副本，保留用户数据和正式更新基线。旧源码与历史文档仍可从上述提交查看；生成文件需重建，不应假设本机归档始终可恢复。
