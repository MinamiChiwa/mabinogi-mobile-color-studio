## 拖拽花屏根因实测 + 框架选型（2026-10-29 02:40）

- 实测环境：Python 3.14.7 / TkVersion 9.0 / customtkinter 6.0.0。
- **根因不是算力**：浮窗移动+flush 仅 4.61ms（217fps），work_area 0.003ms，geometry 请求 0.004ms。
- 真因三条：
  1) Tk one-widget-one-HWND：浮窗 32 个原生窗口、主窗 278 个 → 父子不同帧提交 = 花屏（非卡顿）；
  2) alpha 一旦设过就永久 LAYERED（exstyle 0x08080088，改 alpha=1.0 也不撤销）→ 每次移动整面重混合；
  3) `<B1-Motion>` 无合并：1000Hz 鼠标 322~366% 帧预算饱和；合并到 16ms 后余量充足。
- 对照证据：主窗 resize 有 `after(16)` 合并，浮窗拖拽没有 → 疏漏而非取舍。
- 选型结论：A（就地改造，80~120 行，可证伪根因）先行 → B（PySide6 Widgets）作终局。
  排除 C(Qt Quick 过度)、D(WebView2 分层+子HWND 同源风险)、E(Slint/egui 需自写浮窗 Win32)。
- 文档：docs/design/ui-framework-selection.md（377 行）。
- 附带修复：search_overlay.py:114 retry_button 重复 height 参数（上轮 V1 引入，浮窗只在开始寻色时创建故未暴露）。
- 已知遗留：test_app_atlas.test_main_window_result_detail_marks_verified_compromise 报 AttributeError，
  经验证**原版 app.py 同样报错**，属仓库既有缺陷，非遗留自本次改动。

## 界面迁移到 Qt Quick（2026-10-29 03:45）

- 新增 `run_qt.py` + `work/studio/qt_ui/`（7 个 .py + 11 个 .qml，共 3791 行）。
- **核心手法：借用方法对象，不复制业务代码。**
  `QtHost.go = legacy.App.go`（同一函数对象），宿主提供 `self.status.configure()` 之类的
  同名属性，由适配器转发到 QML 状态。实测 16/16 业务方法 `is` 原版。
- 圆角三层：Window color=transparent + 圆角 Rectangle（12/10），
  内层卡片 10、控件 6、色块 5。实测四角像素透出桌面 → 真圆角。
  按要求**不做整窗透明度**。
- 浮窗保留原生能力：仍调 `overlay_native.configure_overlay(hwnd, passive=True)`，
  实测返回 `capture_excluded: True`（SetWindowDisplayAffinity 0x11 生效）、
  `passive_input: True`（WS_EX_NOACTIVATE）。
- 已迁移：主窗、三列卡、浮窗、色板查看器、教程/支持、历史、方案、窗口选择。
  **仅「检查更新」仍走 Tk**（updater/ 冻结）。
- 踩坑记录（重要）：
  1) QML 里 `property var state` 会把 setContextProperty('state') 遮蔽成 undefined；
  2) `state` 本身是 Qt Quick 内置属性（Item.state），**必须改名**为 uiState；
  3) 根元素 `id: card` 与 `property var card` 同名 → 属性被 id 遮蔽，绑定全 undefined；
  4) `@Slot` 方法在 QML 里可调用，但若被上述遮蔽会报 "not a function"；
  5) Repeater 不自动注入 index（那是 ListView 的 required property 机制），要显式传；
  6) 无边框窗口必须自己加 DragHandler + 右下角缩放手柄；
  7) 截图核对 DPI：geometry 是逻辑像素，ImageGrab 要乘 dpr，否则只截到左上角一半。
- 验证：7 个 QML 全 0 告警；端到端 12 项 + 界面 16 项全过；
  冒烟 56/56、契约 15/15 通过；1280/1100/1000 三档卡片等宽不溢出。

## 严重缺陷：run_qt.py 属性名不匹配导致界面全白（2026-10-29 20:20）

**用户截图反馈"界面长这样"——浅灰底、白卡片、深色字，完全不是深色主题。**

### 根因
`run_qt.py` 注入的是 `setContextProperty('state', host.state)`，
但 QML 里全都用 `uiState.`（早期调试时改名，忘了同步启动入口）。
→ `uiState` 为 null → 所有 `themeColor()` 调用失败 →
QML 回退到 Rectangle 默认白底、Text 默认黑字。

### 为什么没被发现（关键教训）
我所有验证脚本都是**手写** `setContextProperty('uiState', ...)` 的装配代码，
**从没真正执行过 `run_qt.py` 本身**。手写装配与真实入口不一致，
测试全绿但真实启动是坏的。**以后必须跑真实入口，不能只测复刻版。**

### 修复
1. `run_qt.py` 改为注入 `uiState`，并加注释说明为何不能用 `state`。
2. **加启动自检**：Main.qml 暴露 `uiStateReady` 只读探针
   （检查 uiState 非空 + themeColor 可调用 + 返回值非空），
   `run_qt.py` 加载后校验，不通过直接 exit 3 并打印原因。
   实测：正确名 → True，错误名 `state` → False。

smoke 56/56、UI 抽样 37/37、真实启动自检通过 0 告警。
