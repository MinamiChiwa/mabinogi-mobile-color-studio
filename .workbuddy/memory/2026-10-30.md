三条路都试过，结论值得记下来：

| 方案 | 结果 |

## V5：六个入口改紧凑浮层 + 卡顿根治 + 进度条常在动画

### 1. 卡顿的根因（不是玄学，是双重循环）

`start_services()` 里既 `QTimer(_tick_timer, 60ms).timeout → tick`，而 `business.tick`
的 finally 又 `self.after(60, self.tick)` 自续。**QTimer 每触发一次就凭空派生一条
永久的 after 链**，tick 频率随时间线性增长：实测 1 秒 135 次/秒、3 秒 595 次/秒
（应为 16.7）。同时 `QtHost.after()` 每次 `QTimer(self)` 只从 dict 移除、从不
`deleteLater()`，于是每秒泄漏 599 个 QTimer，10 分钟可累积 36 万个。

修法：
* `start_services` 只 `self.after(60, self.tick)` 踢一次，让 tick 自续（与 Tk 版一致）；
* `after()` 的 fire 里 `timer.deleteLater()`。

效果：tick 595 → 15.8 次/秒（恒定），对象增长 +1800/秒 → **0**。

### 2. 单个事件 7ms：emit 太贵

cProfile 显示 50 条事件耗时 441ms，其中 245ms 是 204 次 `changed.emit()`
（每次约 1.2ms，因为绑定到它的 QML 表达式很多）。而 `business.tick` 一次要处理
最多 50 条 → 单次 tick 369ms，队列积压 5101 条，界面自然卡。

修法：`UiState` 与 `OverlayState` 都加合并发射——`_emit()` 只置标志并
`QTimer.singleShot(0, _flush)`，一轮事件循环只发一次。属性值本身是同步写入的，
读值不受影响，只有通知延后一帧。

效果：tick 中位 369ms → **1.96ms**（p95 3.08ms），队列积压 5101 → 1。

### 3. 浮窗心跳也在漏

`heartbeat()` 每秒 `QTimer(self)` 新建一个且开头把 `_heartbeat_timer = None`，
复用形同虚设。改成只在为 None 时创建、`_stop_heartbeat` 只停止不销毁。
修正后浮窗 6 秒对象增长 +5 → **0**。

### 4. 进度条「停在某处」

原来确定性模式是静态宽度。改成两条独立通路：
* `progress < 0` → 38% 滑块来回扫（`progressSlide`）
* `progress >= 0` → 宽度平滑过渡 + **常在流光**（`sheen`，与数值无关恒速移动）

逐帧 diff 验证：进度固定在 0.5 时，进度条区域 4 帧间仍有 174 个像素变化。

### 5. 六个入口改紧凑浮层

自动检测 / 支持作者 / 检查更新 / 使用教程 / 保存方案 / 寻色记录 → 复用已有
`Popover`（自带锚点定位、方向自适应、点外部关闭），新建 `QuickPanel.qml` 按
`kind` 渲染六种内容。`Main.qml` 根级记录 `panelAnchor` + `panelKind`。
GitHub 仍直接开浏览器。

验证：六个入口 `topLevelWindows` 数量均 1→1（不再新建窗口）；尺寸 300×79~365。

### 踩到的坑

* **QML 的 Item 不通过 QObject 父子暴露**：`win.contentItem().findChildren(QObject)`
  只返回 2 个，必须用 `childItems()` 递归遍历才能拿到 objectName。
* **`objectName()` 返回 QAnyStringView**，`if o.objectName()` 恒假，要 `str(...)`。
* **`property var uiState` + `uiState: uiState` 会自引用成 undefined**，
  组件内直接用上下文属性即可。
* **中文 `Text.WordWrap` 不断行**（中文无空格），要 `WrapAtWordBoundaryOrAnywhere`；
  且 `width: parent.width` 在委托里首次布局时会按旧宽度排版再按新宽度裁剪，
  末尾字被切半个 —— 改成引用稳定的外层 `tutList.width - 8`。
* **ColumnLayout 的隐式最小宽度会把内容顶出浮层**（按钮被挤出右边界），
  要么 `body.implicitWidth: 0`，要么把「输入框 + 按钮」拆成两行。

## V6：浮层开关失效 / 刷新按钮多语言 / 吸管色块 / 交互审计

### 1. 浮层关闭后再点没反应（根因是绑定被销毁）

`Main.qml` 里原本写 `Popover { open: root.panelKind !== '' }`。
`Popover.close()` 内部执行 `open = false`，**命令式赋值会把这条绑定永久销毁**，
之后 `panelKind` 再变也不会驱动 `open`。复现：点按钮→点空白→再点按钮，
`open` 恒为 False。

修法：`open` 改为命令式驱动（`openPanel()` 里显式 `quickPanel.show()`），
不再挂绑定；`onOpenChanged` 只负责清 `panelKind`。

顺带把「浮层开着时点另一个入口要两次点击」也修了：给 `Popover` 加
`topInset`，遮罩从入口栏下沿开始，入口仍是可点区域，一次点击直接切换。
`topInset` 用布局常量算（`padTop + appBarH + pageGap + envBarH`）——
**绑定里调 `mapToItem` 不会依赖祖先布局变化**，只会算到布局完成前的值（46 而非 109）。

English 也只显示 `Refre`。修法：
* `QuickPanel` 宽度跟随 `parent.width`，去掉自己那层 12px 内边距（Popover 已提供）；
* 标题 `fillWidth + minimumWidth: 0 + elide`，刷新按钮 `Layout.minimumWidth: implicitWidth` 不允许被压缩。
另补了 JA/KO 的浮层面板文案（此前回落中文）。

## V8：吸管点击无效（Slots + 段错误）/ HSL 滑块不能拖动

### 1. 吸管「点了没反应」是两处叠加

**(a) 方法没进 Qt 元对象。** `QtEyedropper.preview/confirm/cancel` 都是纯 Python 方法，
没有 `@Slot`。QML 里 `eyedropper.confirm()` 调不到，静默失效 —— 全屏取色层能出现，
但单击/右键/Esc 全无反应。元对象实测只暴露 `['_poll_escape', 'start']`：
这两个之所以在，是因为它们被 `QTimer.timeout` / `singleShot` 连接过，PySide 顺带
注册成了槽，把问题掩盖了。

修：`@Slot(float, float, result=str) preview`、`@Slot() confirm`、`@Slot() cancel`。

**(b) 收尾时同步销毁引擎 → 段错误。** `_finish()` 原来在**当前调用栈里**就把
`self._engine = None`、`window.close()`。而 `confirm()` 是从 QML 的 JS 栈调进来的，
引擎在 JS 仍在执行时被析构 → use-after-free，实测 exit=139（应用直接闪退，
表现同样是「点吸管没反应」）。

修：`_finish` 只把 `_window/_engine` 摘下来，真正的关闭与释放交给
`QTimer.singleShot(0, teardown)`；engine 用 `holder = [engine]` 持有，
`teardown` 里 `holder.clear()`（闭包里 `del engine` 会变成局部名，报 UnboundLocalError）。

验证：QML 调 `confirm()` 后 target 从 `''` → `#141414`，picking 复位，exit=0 无崩溃。

### 2. HSL 滑块只能单击、拖不动

`InlineColorPicker.qml` 里三条滑块的 `Repeater.model` 是**内联 JS 数组**，
元素里直接引用 `card.pickerHue/pickerSat/pickerLig`。于是每次 `pickerSlide`
→ 状态更新 → `card` 重新求值 → 数组被重建 → Repeater **销毁并重建全部委托**，
鼠标抢占立刻丢失。实测按下后控件对象直接被删：
`RuntimeError: Internal C++ object (QQuickItem) already deleted`。

修：`model: ['hue','sat','lig']` 静态 key 列表，动态部分（min/max/value/label/
suffix/三条轨道色）改成委托内的 `readonly property` 绑定；`modelData.*` 全部
换成 `sliderRow.*`。委托对象从此稳定，绑定照常更新。

验证（真实按下+移动）：
* 饱和 25→35→50→65→80→95 连续 7 次回调
* 亮度 20→35→50→65→80→90→95
* 色调 72→125→180→233→288→341（中性色时按设计禁用）
