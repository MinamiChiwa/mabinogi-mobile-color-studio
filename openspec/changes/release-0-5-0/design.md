# 发布设计

## 决策

保留已通过离线测试的生产源码；文档和发布元数据同步后提交，再从该提交构建正式包。通过源码指纹和逐模块字节码比较核对新旧包，不能将旧构建中的提交号改写成未经实际构建的新提交。

正式包沿用生产公钥和既有签名设施。私钥只在本机内存中参与签名。上传前验证版本、渠道、递增序号、所有 blob 及完整安装包，并在独立测试目录演练旧版升级与数据保留。

发行使用草稿暂存上传；资产齐全并通过校验后转为公开 stable 发行。公开后从 GitHub 和镜像检查发现结果与签名。网络失败须保留事实，不宣称已验证。

## 文档边界

五语文档统一版本、包名、最近 10 次会话保留及兼容发现限制；历史日期报告保留原有结论，并以状态说明连接到 0.5.0。用户同意发布不作为新的游戏实测数据。

## 文件保留

完整 ZIP 直接放根目录“发布包”；签名资产和验证证据留在 artifacts。成功交付才清理已确认生成的旧候选包，未知或修改的文件及个人数据保留，受阻生成文件移入“待删文件夹”。正式更新基线不随候选清理删除。
