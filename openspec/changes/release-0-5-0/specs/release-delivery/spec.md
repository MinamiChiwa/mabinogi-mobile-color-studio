# 发行交付规格

## Purpose

为使用者提供版本一致、可验证且可追溯的完整安装包与在线更新，使使用说明准确反映已交付行为，并在更新和本地整理时保留个人记录与必要基线。

## ADDED Requirements

### Requirement: 交付内容对应源码

正式发行 SHALL 关联包含其生产源码的 Git 提交，并保持构建身份、安装包版本和发行标签一致。

#### Scenario: 从批准版本构建正式包
- **WHEN** 用户批准本地测试版本发布
- **THEN** 正式包通过生产模块、资源和版本校验，构建提交可用于追溯对应源码

### Requirement: 在线更新签名与完整性

stable 更新 SHALL 使用已有生产信任身份，并使用高于上一正式版本的发布序号。

#### Scenario: 旧版安装升级
- **WHEN** 旧版安装接收新的签名更新
- **THEN** 清单与文件哈希通过校验，更新到目标版本，并保留设置、方案及个人记录

### Requirement: 五语文档一致

五语使用说明 SHALL 指向同一正式版本，并准确说明功能限制、安装方法及会话保留行为。

#### Scenario: 查看 0.5.0 说明
- **WHEN** 使用者打开任一受支持语言的当前说明
- **THEN** 下载包名为 0.5.0，诊断会话说明为最近 10 次，并说明台韩兼容发现可能拒绝不兼容客户端

### Requirement: 本地包集中与保留

本地完整包 SHALL 集中放在根目录“发布包”，仅在新包构建和验证成功后清理已确认生成的旧候选包。

#### Scenario: 新包交付成功
- **WHEN** 新完整包和程序校验完成
- **THEN** 使用者能从“发布包”直接找到 ZIP 和程序目录，旧生成包被清理，个人记录、未知文件及必要正式基线保留

#### Scenario: 新构建失败
- **WHEN** 构建或包校验失败
- **THEN** 旧可用候选包不因这次失败被替换或删除
