# 2026-09-29 19:14 会话失败复核

## 现象

会话 `20260929-191405-4d61db2e` 设置为两个相似蓝色区域（`#0000FF`）和一个精准白色区域（`#FFFFFF`）。发布的第一候选预测为 `#69268F / #A959B0 / #F4F1F3`，两个相似区域对目标的预测色差为 70.31 和 84.23。它们属于紫色或紫红色，不能作为蓝色系妥协方案。

执行时第一次路线重规划正确保留了旋转目标，但后续切换到平移备用时，备用路线绑定在当前实测姿态，执行器却把它当作开局参考，导致目标矩阵少乘一次当前姿态。之后平移无法收敛，恢复读数为 `#AE7322 / #663D42 / #7DC08A`，色差为 171.93 / 127.73 / 47.56，且姿态不可信。

## 代码修订

1. 色系判断增加独立的 sRGB HSV 色相约束。Lab 色相在蓝色与紫色之间会出现压缩，单独使用 Lab 色相会把 `#69268F` 和 `#A959B0` 误判为蓝色系。蓝色候选现在必须同时满足 Lab 和 RGB 色相范围；RGB 色相差超过 20° 时判定为色系偏离。
2. 取色点邻域的色系门槛改为严格零超限。容差超出仍可作为同色系妥协，色系偏离则不能作为稳定落点发布。
3. 所有从实测姿态返回的重规划路线统一通过 `_adopt_bound_route` 提升到本次执行的累计姿态。其目标、预期姿态和轨迹均包含已完成的实测变换，避免将局部平移误当作开局坐标。
4. 绑定路线和无绑定平移重规划均重新设置路由索引、累计误差和翻转状态，避免旧路线状态污染新的实测路线。
