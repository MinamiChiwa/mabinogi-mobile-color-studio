## 已修复的正式链路问题

1. **采集参数不同步。** `atlas_live_adapter.acquire_current()` 之前没有传 `row_stagger`，实际为 0；已明确传 `.05`，与用户验证的入口一致。
2. **正式图板分辨率。** `atlas_adapter.build_from_capture()` 之前仍用 768，现显式使用多局已通过 RGB 质量检查的 1024。离线分析 CLI 仍支持 768 对照；没有提高 RMSE 门槛。
3. **执行器跨材质 RGB 误判。** `atlas_runtime.motion()` 原先将纹理从一个材质移入另一个材质后的颜色用于直接差值，正常运动也会判失败。新实现用同一套材料遮罩，只比较同材质且四邻采样像素全有效的区域；每区至少 32、总计至少 200 个样本，每区 RGB RMSE≤10。
   - 修改前本局抽查的 8 组正常拖动全部返回 None。
   - 修改后本局 48 组相邻实拍全部通过；最大整体 RGB RMSE **1.245568**，各区最差 **1.745485/1.577157/1.278129**；矩阵平移与指令最大差 **0.144097 像素**。
   - 这不是 0.035 像素微移精度验收，也不是实时往返验证。报告 `runtime-motion-before.json` / `runtime-motion-after.json`。
4. **候选落点敏感性。** `translation_candidates(...,landing_radius=1.)` 增加周期边界环绕的邻域筛选，优先选择一小片范围内均在容差内的候选。无效像素不能成为可靠邻域。新 `candidate_ranking.py` 统一搜索结果、Service 和 Batch 的默认候选排序，避免展示一种、执行另一种。预测稳定性仍不保证游戏 HEX。

## 新增颜色优先的联合搜索（离线，尚未接入执行）

`atlas_similarity.py` 在各材质图上寻找目标色像素，保留空间分散的种子，使用两组颜色位置与取色点拟合共同的旋转/缩放/平移；第三色必须通过同一个变换，不能各自独立平移。周期等价点允许跨图板边界。返回的 `matrix` 是从当前参考截图到候选的板内坐标变换，dx/dy 是板中心位移，兼容已有 `planner.decompose_gestures()`。
