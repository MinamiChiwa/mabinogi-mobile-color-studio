## 找到的具体答案

### 截图色块的 RGB 并不总等于显示的 HEX

54 个色卡文字已在 `cards-review.png` 逐项目视核对；其中暗色有明显差异：

|游戏文字|色卡内部截图 RGB|直接 RGB 距离|
|---|---|---:|
|#080803|(13,13,0)|7.68|
|#000406|(0,0,0)|7.21|
|#000508|(0,0,13)|7.07|

使用标准 sRGB 传递函数检验如下显示模型：

`HEX → sRGB 解码为线性亮度 → 四舍五入量化到 8 位 → sRGB 编码 → 截图 RGB`

本轮全部 54 个色卡与该模型的最大 RGB 欧氏残差 **1.73**，各通道最大绝对残差 1；上一局已经目视验证的 18 个留出色卡也全部在 1.73 以内。
该结果支持显示链路中存在与 8 位线性亮度量化相符的现象；不能据此断言具体引擎、纹理格式或 GPU 实现。
也不能把色卡显示转换直接当成图板连续纹理的完整模型。

### 细色带需要重建形状和亮度关系，固定坐标补丁不足

区域 2 的横向色码从 #52501E、#3A3815、#21200C、#080803 连续经过近黑色，再进入蓝色；纵向微移反向穿过这条色带。
普通截图双线性取样混合了相邻像素中的两侧颜色，不能重现中间的暗谷。
这组观测不支持在当前尺度上直接采用最近屏幕像素作为实际取色；它不能排除更细纹理格点上的其他取样规则。

局部诊断采用以下隔离：

1. 可见 max_sampling 原生像素提供色带两侧的空间形状；圆环几何及配准不使用 HEX。
2. 只使用 probe_000…008 的 9 个横向 HEX，拟合固定横向偏移和局部两侧 RGB 系数。
3. probe_009…016 的 8 个纵向 HEX 不进入损失函数。
4. 这是看到完整轨迹后选择模型的探索性验证，不是事先锁定的盲测。配准可以使用所有帧的可见纹理。

|模型|横向标定 RGB RMSE|纵向验证 RGB RMSE|纵向最大 ΔE76|
|---|---:|---:|---:|
|截图最近像素 + 固定偏移|25.50|90.80|73.60|
|截图双线性 + 固定偏移|23.51|35.42|30.35|
|截图双三次 + 固定偏移|17.81|30.16|24.17|
|局部两侧斜坡，未经亮度线性化|7.02|9.88|11.53|
|局部两侧斜坡，标准 sRGB 亮度线性化|1.15|4.54|5.75|

最后两行除传递函数外使用同样的局部像素选择与拟合流程。标准 sRGB 模型对可见原生红、蓝斜坡像素的拟合 RMSE 为 2.15 / 0.39；直接在显示 RGB 空间拟合是 10.49 / 4.96。
因此改善同时涉及色带结构重建与亮度线性化，不能把 30.35→5.75 全部归因于单个 gamma 操作。

证据图为 `findings.png`。该图中的两个预测方法都使用本轮仿射几何，且各自仅以横向点标定。
5.75 仍不是精确 HEX 命中；模型限于本次区域 2 的一条黄/黑/蓝色带，尚未证明可迁移到其他色带或随机局。
尤其此前 grid_030 区域 2 的大色差**尚未被这份局部模型修复**。

### OCR 的宽松提前接受确实会制造错误 HEX

原始 `codes.json` 保留不改。目视确认的两处修正单独记在 `verified-codes.json`：

- probe_006 区域 1：#714124 → **#71412A**。
- probe_006 区域 2：#0C1E1F → **#00161F**。

原先与色卡 RGB 距离小于 12 就提前接受、最终小于 18 就通过，会放过这些合法六位字符串。
`vision.read_codes` 现在用原始显示或上述量化显示模型校验 OCR，要求距离小于 3；不匹配则继续其他已有 OCR 变体/分字识别，仍不匹配返回 None。
只校验识别出的文字，绝不由色块反推或猜写 HEX。保留直接显示匹配以兼容没有量化差异的画面。
这个小于 3 的门槛是更严格的色码校验，不是放宽 atlas 质量门槛。

保存图片回放：本轮 **54/54** 自动识别正确，上一局留出 **18/18** 正确；本轮 OCR 耗时 10.71 秒是批量离线读取 18 帧，不是实机路径时间。
这只证明已检查样本；其他字体/显示路径可能返回 None，不能保证所有未来 HEX 都不会误读。
