# 2026-09-29 最终候选明显变差的复核

## 现象

会话 `20260929-164307-de1309fb` 在 1280×960 客户区完成采样和定位。三个目标为两个相似蓝色区域与一个精准白色区域。初始候选预测为 `#5A5FAE / #5777BE / #FFFFFF`，随后实际最终结果为 `#9478BD / #1895CB / #DAE6D5`。最终三区对目标 ΔE76 为 `39.16 / 46.70 / 14.11`，精准白色未命中。

## 原因

1. 原候选需要较长的离散旋转、缩放和最终平移路线。前两次旋转的实测响应出现偏差，程序正确地丢弃了剩余旧路线并重新测量当前位置。
2. 旧恢复逻辑在“整条路线最多两次重绑定”后，直接调用平移型备用搜索。该限制没有区分“动作仍在持续接近目标”和“动作没有响应”；本局在仍有约 37 秒、剩余路线估算约 10.3 秒时提前退化，最终候选预测变成 `#8773D1 / #3890C5 / #DBE8D7`，白色已偏离。
3. 最终实测颜色与该退化预测的差异为 `14.40 / 4.33 / 0.72`。因此屏幕配准本身通过，并不能说明候选选择正确；是执行路线恢复改变了候选目标。
4. 用户选择的候选 id=1 没有执行，日志把 `no_measurable_motion` 显示成“剩余时间不足”。实际是从当前位置到该候选的离散路线不可可靠生成，提示不准确。

## 已修正

- 重绑定不再以固定两次作为唯一上限。只有在已经完成多个动作、且实测目标误差相对上次重绑定继续明显下降时，才允许延长重绑定；无响应、反向滚轮和无法生成有效整数动作仍立即进入已有备用路径。
- 候选最终实测色差若比默认候选重新计算前明显变差，即使仍属于同一色系，也会按统一候选质量排序尝试更好的可执行候选。不会继续保留明显变差的默认结果。
- 选择候选时区分 `deadline`/`insufficient_time` 与 `no_measurable_motion`、`unreachable_scale` 等不可达原因；后者提示“所选方案无法从当前位置可靠到达，已保留当前颜色”。简体中文、繁體中文和 English 已补齐。
