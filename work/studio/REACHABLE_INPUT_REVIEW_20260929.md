# 离散动作一致性与参考工具审查

日期：2026-09-29。范围：离线程序集检查、动作输入层修订、保存记录回放；未发送游戏输入，未打包或发布。

## 结论

参考工具中可确认存在整数鼠标轨迹、分方向滚轮响应、动作后测量、颜色连通区稳定性和失败动作记忆。这些机制适合补强本项目的操作与验证层。它们不能替代本局拼图，也不能证明任意连续颜色解均可由游戏输入实现。

本项目已将平移、旋转、缩放的整数轨迹和请求时序抽离为纯数据描述，规划和 Windows 输入层共用生成器。正式执行每一步先生成动作描述，再将同一对象交给输入层，并保存到指令及测量日志。取整后没有角位移的圆弧不再发送右键输入。22 条历史轨迹逐点对照一致，既有旋转轨迹与等待节奏保留。

这完成了里程碑 A 的输入一致性部分。预算仍以名义旋转响应推演后续姿态，并显式标记为未完成游戏响应验证；它不是阶段 C 要求的、经过响应范围验证且重新算色的完整绑定路线。

## 不应直接采用的部分

- JointMotion.ZoomFactor（0x060001d6）在缺少测量时仍可使用默认放大 1.01、缩小 0.99。它区分了方向，但默认值本身不是当前设备、当前档位的实测证据。
- JointMotion.Next 仍含无响应、重复微移和档间缩放等停止路径，不能据此认定其流程已经解决所有恢复问题。
- SearchPlanner.Score 使用 RGB 通道容差超额之和；本项目使用 ΔE 及精准区域均衡策略，评分口径不同，不能比较或照搬数值。
- 部分局部精调包含保护已命中部位的约束。本项目不得因此退回“保住一个精准白色、牺牲另一个精准白色”的旧排序。
- 参考工具根据当前画面及局部候选纠偏。本项目继续执行“先拼本局大图、再找色、再规划”的既定主线。

## 本轮源码变更

- input_gestures.py：平移、旋转、逐档缩放的不可变描述；物理客户区整数坐标、支点、按钮、请求等待、几何圆弧角及记录格式；有界纯几何缓存。
- platform_win.py：直接发送已规划的动作描述；重复坐标仍保留等待；按下动作异常也尝试释放按钮；无效圆弧在输入前排除。
- atlas_execution.py：预算生成对应的输入描述，执行每一步使用同一描述进行发送和记录；几何上无效的旋转保留当前实测姿态进入现有重搜索路径。
- atlas_runtime.py、atlas_trial.py：传递原动作对象，不在输入层重新生成路径。
- gesture_replay.py：只读提取保存指令、实测矩阵及未测得响应的失败命令，并按会话划分训练与检查数据。支持导入旧审查保留的旋转记录，且明确其非完整事件流的来源。

动作描述中的等待时间是请求值，不是 Windows 调度或游戏接受事件的实际时间保证。当前闭环仍在每步测量后重算余下动作；没有将预算中的名义姿态直接写成实测姿态。

后续补充：同日原始外部会话已恢复。完整事件重新读取结果为 71 条定位测量，旋转统计与本报告一致；仅 7 组最后截图可重新配准。数据范围及新代码验证见 [动作响应与最终姿态报告](RESPONSE_EVIDENCE_20260929.md)。

22 条保存的整数旋转路径与新生成器逐点一致。三类数据分别保留为请求角度、整数圆弧几何角度和图像配准测得角度；不相互替代。

按会话留出检查一个参数的比例增益，结果如下。每次拟合只使用其他会话；仅用于离线比较，没有把拟合参数写入运行时。

|---|---:|---:|
|原请求角度|0.04499°|0.27299°|

## 下一步与最小必要证据

1. 优先从正常定位过程收集新增动作描述及实测响应，按板尺寸、DPI、支点位置、圆弧半径、方向和动作幅度分组；保留无响应与测量失败，不只收集成功动作。
2. 若正常定位不足以区分响应差异，再使用手动进入的一局进行有限诊断：中心及偏心两个支点，分别覆盖正常旋转与接近量化边界的正、反向动作。每次记录前后稳定截图；按实测矩阵累计姿态，不把正反动作视为严格复位。不得自动开新局或确认染色。
3. 用独立会话验证响应范围后，实施阶段 C：连续颜色组合先量化为完整动作路线，再依据路线最终姿态重新取色，并检查误差邻域是否跨越色带。不能只修正角度而沿用原预测 HEX。
4. 将参考工具的稳定颜色连通区和失败动作记忆纳入阶段 C/D 对照。参数以本项目记录确定，且精准区域最大、平均色差优先的规则保持不变。
5. 可靠性验收后比较圆弧分段、重复姿态缓存和候选粗筛的耗时。当前没有新实机耗时证据，不给出未经测量的节省秒数，也不削减已验收拼图帧。
