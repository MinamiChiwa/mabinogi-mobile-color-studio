# 实机机制验收门槛

状态：验证中。适用于当前 0.3.6 / balanced-landing-single-zoom-v3。

## 当前定位

0.3.6 已完成代码回归、安全保护和构建检查，但它是**带限制的技术候选/验证中构建**，不是已经完成游戏机制验收的稳定版。它曾被同步到 main、v0.3.6 标签和 GitHub Latest 发布页；这个发布事实不改变证据边界，也不能把自动化结果解释成实机验收。

自动化回归、截图回放、几何模拟和输入回放只能证明代码行为或离线模型行为。只有真实游戏中连续观察到游戏 HEX、动作前后画面和倒计时，才算机制证据。

当前受控入口为 `run_response_probe.ps1`。它只记录实验，不安装生产响应模型，也不执行确认、应用或取消染色；输出中的 mechanism_experiment.json 缺失字段保持 null。

## 已有证据可以说明什么

- 已有运行记录证明单区域精确命中、单区域未命中的妥协提示、只读 fallback 和多区域未知姿态保护能够被记录和显示。
- 2026-10-08 默认生产回归为 690 项通过、0 跳过；pytest 全量为 851 通过、19 跳过、0 失败。实验、旧流程和私有素材用例分组统计，见 TESTING.md；跳过项不构成真实游戏验证。
- 上述结果不能证明新单区域缩放策略、跨局稳定性、三点共同变换的可达性或多区域在 120 秒内的精准率。

## 尚未通过实机验收的机制

1. 平移、旋转、滚轮上下方向、滚轮步长和缩放倍率响应是否与模型一致，以及是否存在倍率极限。
2. 每次动作后是否必须重新配准；配准可复用的条件、耗时和 120 秒预算影响。
3. 不同局的染色板是否相同，是否存在滤镜、局面或设备差异。
4. 一个像素量化误差为何会造成完全不同的游戏 HEX，以及可否通过实测反馈消除。
5. 三个区域共享一个位姿时，低色差或精确三色组合的可达性、候选切换成本和剩余时间表现。

## 发布闸门

在用户认可的真实游戏实验报告完成前：

- 不把离线预测、回放或自动化回归写成“机制已验证”。
- 不以当前 0.3.6 作为精准率或跨设备稳定性的承诺。
- 不发布新的正式版本，也不通过同版本重打包掩盖未完成验收；若实验后有代码变化，使用新的版本号并在发布说明中列出实验依据。

实验应尽量在同一局、只消耗一次染色剂完成，记录每个动作前后截图、三个游戏 HEX、动作方向/步长、配准耗时和剩余倒计时。报告必须分别标注“已观察”“基于观察的推断”“仍未验证”，并由用户确认后才能改变发布定位。

## 后续真实实验门槛

前述 `baseline / translation_shared` 机制实验和一次正式多区域回归均已完成；不再把 `translation_shared` 写作待执行实验。下一次真实游戏实验必须先明确实验目的和预计消耗（当前按一局、一次正式染色计 1 枚染色剂），并由用户确认后再开始。优先选择以下两类之一：

- 重复验证旋转/滚轮响应：只观察动作前后画面、配准、倍率/位姿和三区 HEX，不把未验证响应接入生产；或
- 目标组合回归：使用可重新配准的平移路线，记录三色 ΔE、候选首次可用时间、返程和双帧复核，补足不同目标组合证据。

若验证连续锚点采集，必须在同一局保持窗口、DPI 和画板状态不变，并保留每个相邻动作的前后截图；不得用稀疏跨区跳跃替代配准。每次实验结束前必须保留返程与双帧复核时间。

后续代理开始工作前必须先读本文件、PROJECT_STATUS.md 和 VERIFICATION.md；遇到“测试通过所以可以发布”的结论时，先检查本门槛。

- 是否可据此减少正式 48 步路线，以及渐进路线的候选质量和返程成功率。
- 本实验没有记录目标色差、精准命中数、正式候选定位时间或染色确认结果，不能作为多区域搜索验收。

### 基于观察的推断

- 这次旧流程因预测无共同达标候选而停止，未执行候选路线。当前图谱质量门通过，但图谱缺色与有限候选集合不足以判定真实颜色可达性，也不能排除搜索遗漏。严格模式下，接近色 `#FFFEFE` 不能当作 `#FFFFFF` 精准命中。
- 当时旧版本在没有共同达标候选时停止自动移动；这保护了当前可复核画面，但会让一次已启动的染色回合失去继续定位近似结果的机会。
- 当前源码已加入 `exact_target_availability` 诊断和更具体的提示，会指出未记录精确目标的区域、目标色、最近采样色和 ΔE。该字段是在本轮会话之后补齐的，不能回写成当时日志已经包含的事件。

### 当前策略修订

- 精准模式表示“精准候选优先”，不表示“没有精准候选就停止”。如果候选预测未达到精准规则，但路线通过质量门、姿态可靠性、稳定落点和剩余时间预算，服务会继续定位综合色差最小的实测妥协候选。
- 妥协结果始终带 `compromise=true`，界面显示“未找到共同精准命中；候选按综合色差排序，实测后保留近似结果，不会自动确认染色”。近似色不会被报告为精准命中，最终是否套用仍由玩家在游戏内确认。
- 建图失败、配准失败、没有安全路线、无法完成返程/双帧复核或时间不足时，仍只读两帧当前 HEX；这些安全停止条件不因妥协策略放宽。

### 仍未验证

- 其它局面或设备是否会出现区域 1 的精确 `#FFFFFF`，以及目标组合是否由关卡或滤镜改变。
- 将区域 1 改为相似模式后，三区共享位姿是否能达到可接受的共同 ΔE；这需要新的目标组合实验，不能用本轮严格模式结果代替。
- 真实游戏确认染色的结果和库存变化；本轮没有确认点击，自动化日志不覆盖程序外手动操作。
