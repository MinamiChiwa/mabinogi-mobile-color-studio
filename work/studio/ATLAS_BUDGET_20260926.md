本轮继续用户已批准的六十秒目标。仅使用两份完整采样、一份已有微移采样；

## 1. 已保留的无损提速

性能剖析发现完整分析重复执行 atlas `maps()` 46 次，累计约 2.43 秒；
同一份 atlas 又保存两份相同的压缩数组，压缩累计约 1.48 秒。
这些数字来自带剖析开销的一次运行，仅用于定位热点。

正式分析现已改为：

- 全部训练帧累积完成后生成一次 `AtlasSnapshot`，后续采样、覆盖、质量与候选使用只读图。
  快照独立拥有数组，后续累积不会修改它，也不是跨局缓存。
- `expanded` 与基础目录当前使用同样的训练帧和地图，因此复制已经完成的导出，避免重复压缩；
  保留现有目录、文件名和内容，便于现有分析工具继续读取。
- 候选计算内部继续检查取消/截止，未修改颜色、768 分辨率、质量门槛、位移或候选规则。

在同一进程中对旧/新实现各运行两次，第二轮交换先后次序：

|完整局|原实现分析中位耗时|新实现中位耗时|减少|
|---|---:|---:|---:|
|2026-09-26 11:38|10.775 秒|6.971 秒|35.3%|
|2026-09-24 21:41|10.419 秒|7.045 秒|32.4%|

两局的周期、全部偏移、覆盖、逐帧留出结果、质量门槛、点位检查完全一致；
两组 NPZ 的所有数组均逐项完全相等。另有合成测试确认快照的采样、有效性、RMSE、
周期等价位移候选和可执行半径约束与原实现一致。

这里的耗时包含读取已有 PNG、配准、建图、质量检查和导出；
两局仍未通过质量门槛，因此都没有计算正式候选。不能把七秒称为整个染色流程耗时。

证据：`outputs/atlas-budget-20260926/timings.json`、`new-equivalence.json`、`old-equivalence.json`。

## 2. 截图保存的无损提速

从新完整局选六张已保存画面，对全图和原生色板裁图成对写入 PNG，每种压缩级别各两轮，
第二轮交换压缩顺序。所有输出都重新打开并与输入逐像素比较。

|PNG 压缩级别|每对图片中位保存时间|每对图片中位体积|像素一致|
|---|---:|---:|---|
|6（原默认）|0.1231 秒|1,381,121 字节|全部一致|
|1（采用）|0.0500 秒|2,003,743 字节|全部一致|
|0（未采用）|0.0352 秒|4,433,450 字节|全部一致|

正式 `snap()` 采用级别 1，以约 45% 文件增量换取更少的 CPU 压缩。
未降低尺寸、位深、采样精度或转换 JPEG。级别 0 再快约十五毫秒，但体积翻倍以上，未采用。
每帧新增实际采集时间、PNG 保存时间和压缩级别日志；避免下一轮把保存开销混入移动时间。
原始抓图时刻另存为 `captured_elapsed_seconds`，旧 `elapsed_seconds` 仍表示日志事件时刻。

该测试使用已解码的图片和已热缓存的文件系统，不包含实时截图、游戏调度或鼠标输入；
因此四十帧可省约 2.924 秒只是估算，尚未在游戏里复测。
证据：`outputs/capture-storage-20260926/report.json`。

保留的留出图纹理仍参与几何配准，因此不是独立几何盲测。

## 4. 微移返回的两个新约束

对现有 17 点逆仿射几何进行审计，以 probe_000 为起点：

- 最大累计相对倍率偏差约 **0.179%**。
- 三个 marker 的位移无法完全用同一个平移表示，最大残差约 **0.277 像素**，
  超过原型 **0.035 像素**容差。该数字来自先前图像配准估计，有测量噪声，不能称为真实引擎误差。
- 单看缩放系数差不超过 0.003 会漏过这种空间漂移，因此离线原型增加了
  `marker_points()` 接口：必须给出与配准矩阵同坐标系的三个点，逐点检查仿射位移相对公共平移的偏离。
  没有点位几何即停止。没有放宽定位容差，也没有将原型接入游戏。
- 保存轨迹全部向前，没有逆向返回和同姿态重复抓图。把矩阵求逆不能证明游戏可逆。

另对六张已核对原生截图各读两次三色 OCR，十二次全部正确：
中位数 **0.437 秒/次**，最慢 **1.307 秒/次**。困难的 probe_006 两次约 1.296/1.307 秒。
因此双次复核加 0.2 秒等待，在这一困难例上已约 **2.803 秒**，还不包含截图和配准。
这不是时间抖动上界，也没有验证实时画面稳定性。

原型原来的试探两秒、验证一秒只是离线假设，现改为试探五秒、验证四秒的保守初值，
返回三秒仍是待验证假设。仍不能据此保证真实返回时间；截止保护始终优先，
无法返回时只保留历史记录，不声称当前位置是最佳。
详细实测前置条件见 `MICRO_RETURN_PROTOCOL.md`。
证据：`outputs/micro-return-review-20260926/review.json`。

## 5. 六十秒现状和下一步

新局已录采集耗时 56.844 秒；减去四十帧 PNG 的估算收益 2.924 秒，
再加本轮新建图中位数 6.971 秒，得到 **60.891 秒**。
这还是跨测量拼接的估算，**没有计入候选、定位、HEX 修正、最终复核或用户选择**。
它说明本轮优化值得保留，但未达到六十秒完整流程目标。
现有采样 48 秒阶段截止仍可能提前中止旧扫描，不能让用户再跑它。

下一步重点不再是简单删图：

1. 先剖析配准在较大位移失败的原因，针对材质分区与 UI 遮挡验证更稳健的匹配，
   再评估同时保留重叠与覆盖的扫描路径。所有候选路线先用现有数据验证能验证的部分；
   未观测的运动与新位置颜色不得合成后宣称实测。
2. 定位期间的鼠标路径、等待与磁盘写入仍占大头。保存日志已拆开计时；
   当前不凭空缩短稳定等待或拖动事件间隔，以免减少时间却损失真实画面。
3. 按返回协议先完成实现和模拟，满足条件后才安排一次用户手动进入的最小微移闭环，
   不重复旧完整扫描、不自动开局、不套用/确认/取消。

整体阶段：**已完成无损计算优化；采集路线和真实微移闭环仍待验证**。
仍没有通过候选精度、最大安全倍率、跨局稳定性或发布验收。
