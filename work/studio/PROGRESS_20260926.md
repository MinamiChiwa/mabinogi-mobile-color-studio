## 本轮新增：较大位移失败的原因

离线读取两局现有截图，比较原匹配、屏蔽 UI、屏蔽 UI 且限同材质对应三种情况。
匹配门槛保持不少于 20 个内点、内点比例不低于 0.5、比例误差不超过 0.005、
角度不超过 0.2 度；没有通过放宽门槛接受结果。

|0→2，约 200 像素横移|全部为 0|全部为 0|全部失败|
|7→8，一次换行|43.40%–46.94%|55.44%–56.66%|全部通过|

|7→23，约 398 像素纵移|16.26%–16.86%|16.51%–16.97%|全部通过|

整块板宽约 498 像素，但每个材质条带仅约 166 像素，有效宽度更小。
整幅图像仍有重叠，不代表同一材质仍共享纹理。横向跳过一帧后约 200 像素位移
使共同有效纹理消失，屏蔽 UI 也无法恢复未被两图同时观察到的纹理。
相同结论在两局复现；不继续对零重叠帧对盲目调匹配阈值。

## 本轮新增：最小正反微移控制器

新增 `micro_return_probe.py`，只有可注入适配器接口，没有实机适配器、CLI 或批处理入口。
执行顺序：基准 A 双次稳定读取 → X 正向一对滚轮 → 双次读取 → 交换锚点请求返回 →
与原始 A 直接配准并双次读取。仅当 X 通过且时间足够时执行同样的 Y 往返。

- X/Y 总计最多八个单刻度滚轮，无额外校正或重试。
- 每个刻度前、鼠标定位后的最末输入边界、等待/截图/配准/OCR 后均检查保护。
- 每个刻度重新检查余量，正向保留正向双读、返回及返回复核，反向保留最终双读；
  两半之间预算不足即停止，不能只因还未到硬截止就继续发送输入。
- 共享截止不会重置，点位阶段另有最多二十五秒；时间预留仍是未校准估计。
- 相对原始基准保存完整仿射矩阵与三个 marker 的逐点位移。
- 返回要求两次观察的三个点均在 0.035 像素内，三个 HEX 逐一相同。
- 停止、配准失败、OCR 不稳定或返回不一致时释放按钮，不强行补齐一对滚轮或返回。
- 历史基准、当前已验证状态、X/Y 完成情况分别记录；部分完成不能标为整个协议通过。
- 新诊断日志被 atlas 分析器明确拒绝，避免误当正式扫描资料。

新增 29 项测试：24 项控制器测试和 5 项材质重叠测试。
控制器测试含每个输入边界逐一中断、每个刻度后中断、两半间余量不足、OCR/几何/
配准失败、位置和颜色不同步返回、X 完成但 Y 预算不足、最终释放失败/超时等。
合成缩放模型中两轴正反恢复原位；这是控制逻辑验证，不是游戏精度证明。

代表性模拟记录：`outputs/micro-return-simulation-20260926/report.json`。
其时钟由测试对象模拟，不能用其中耗时作为实机性能数据。

## 仍未理解或未证实的关键问题

1. 配对滚轮实际反向运动是否足够可逆？此前十七点均为前向路径，不能用矩阵求逆代替实测。
2. 实际图像配准能否可信地区分 0.035 像素误差？此前累计三点残差约 0.277 像素，含测量噪声。
3. 怎样的采样路线既保留同材质纹理重叠，又保持颜色覆盖和留出点支持，同时留出反馈时间？
4. 真实游戏取色和显示的全部差异尚未解释；控制截图无损不能推出实际取样模型已解决。
5. 放大 48 步只是当前预算上限，仍没有证明已经达到游戏最大安全倍率。

1. **继续离线路线设计。** 将同材质重叠作为硬约束，比较纵向优先或调整换行顺序的方案。

   共用六十秒和真实倒计时截止；全程记录实际颜色误差。质量门槛失败仍不发布候选。
5. **跨局稳定后完成发布。** 再固化参数、UI 与错误提示，并整理历史入口。
