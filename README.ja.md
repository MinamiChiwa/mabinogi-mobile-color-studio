# Color Studio · マビノギモバイル

作者：**南千和（MinamiChiwa）** · [愛発電](https://afdian.com/a/minamichiwa) · [Patreon](https://patreon.com/chiwaminami)

マビノギモバイルの染色で目標色を探す、Windows 向けの自動カラー検索ツールです。台湾・韓国・日本の各サーバーに対応しています。**韓国版と日本版はテスト中です。** 標準の「精密検索」は今回の染色パレットを読み取り、移動・拡大縮小・回転の経路を計画して、ゲーム内のカラーコードを再確認します。「スクリーンショット検索」は精密検索が動作しない場合に使う方式です。ゲームメモリを読み取らず、元のスクリーンショットから採色・位置合わせを行い、実際の HEX で結果を確認します。

ゲーム内での使用にはリスクが伴う可能性があります。慎重に使用してください。支援は任意で、機能に差はありません。本ツールは AI の支援を受けて開発しています。

## 使い方

[GitHub Releases](https://github.com/MinamiChiwa/mabinogi-mobile-color-studio/releases) から **`ColorStudio-v0.4.3-Windows-x64.zip`** をダウンロードし、すべて展開して `ColorStudio.exe` を実行してください。`_internal` フォルダーも必要です。Python や Tesseract を別途インストールする必要はありません。

1. 左上で台湾・韓国・日本のサーバーを選び、対応するゲームウィンドウを選択します。ウィンドウが 1 つなら自動検出も使えます。固定解像度の設定や追加の事前チェックは不要です。ゲームウィンドウのサイズと Windows の表示倍率に合わせて座標を調整します。
2. 染色したい部位を有効にし、HEX の入力、色の選択、または画面上のスポイトで目標色を設定します。代替色も許容する目標として扱います。
3. 部位ごとに「HEX 完全一致」または「近似色」を選びます。完全一致は 6 桁のカラーコードが同じ場合のみ達成と判定します。近似色はその部位の許容色差 ΔE で判定します。
4. 部位の優先順位を設定します。1 が最優先で、すべての有効な部位の目標達成を最優先します。妥協が必要な場合は、優先順位に沿って目標達成と色差を順に比較します。色差は ΔE 0.5 刻みで比較し、高い順位の部位のごく小さな差だけで後続の部位の改善が妨げられないようにします。低い順位の部位の完全一致が、高い順位の部位の大きな改善より優先されることはありません。近似色では許容色差内に入った部位より、後続の部位の改善を優先します。順位を変えると、別の部位と自動で入れ替わります。
5. **F8** または「検索開始」で開始し、案内を待ってからゲームの染色画面を手動で開きます。染色画面を開いた後でもツールを開始できます。通常は「精密検索」を使い、動作しない場合に「スクリーンショット検索」を使用してください。
6. 自動操作中はゲームを前面に保ち、なるべくマウスを操作せず、ゲームウィンドウを移動・サイズ変更しないでください。**F9** でいつでも停止し、マウスを解放できます。ツールが染色を開始したり、結果を適用・確定したりすることはありません。使用するかどうかはゲーム内で決めてください。

染色パレットはその回の染色と結び付けて扱います。複数の部位は同じ移動・拡大縮小・回転を共有するため、目標色の組み合わせに同時に到達できるとは限りません。計算上の候補にも実行可能な経路とゲーム内カラーコードの再確認が必要です。予測色だけでは目標達成を確認したことにはなりません。すべての目標を満たせない場合は、優先順位に従って最良の実測結果をできる限り保持します。近似結果を完全一致として表示することはありません。

精密検索では予測候補を表示しません。フローティングウィンドウの **「再検索（テスト用）」または F7** で現在の検索を終了し、ホイールを下に回して染色パレットを最大表示範囲まで縮小してから、同じ染色で検索し直します。残り時間と目標設定を引き継ぎ、新しい染色アイテムは消費しません。縮小と再検索に必要な時間が足りない場合は、現在の色を保持します。スクリーンショット検索では今回取得済みの画像を再利用できます。**F9** は引き続きすべての操作を停止します。

今回の染色パレットを初めて検出してから約 30 秒間、残り時間の読み取り値は参考として扱います。その後は、確実に読み取れて連続して減少するスクリーンショットの値だけで操作期限を調整します。再試行でこの猶予や染色の制限時間がリセットされることはありません。現在の状態を再確認できない場合、過去の色は「前回の実測（現在は未確認）」と表示します。ゲーム内の現在の色を確認してください。

**2 部位・3 部位の染色パレットを自動認識**します。2 部位の場合は実在する左右の部位だけを対象にし、メイン画面の部位 3 は「今回使用不可」と表示します。保存済みの設定や優先順位は変更しません。存在しない部位 3 だけが有効な場合は操作を行わず、部位 1 または 2 を有効にするよう案内します。

革や木材など、素材の基本色に純黒や純白が含まれない場合、`#000000` や `#FFFFFF` に完全一致させることはできません。実際のゲーム内カラーコードを確認してください。複数部位の完全一致の成功や、制限時間内に全体の最良解を見つけることは保証できません。

## 設定とプリセット

- 目標色、代替色、有効な部位、一致条件、許容色差、優先順位、検索方式は自動保存され、次回起動時に復元されます。
- スポイトは固定したスクリーンショットと物理マウス座標を対応させます。ゲームウィンドウを移動したり、強制的に前面へ切り替えたりしません。仮想デスクトップの原点が負の座標でも使えます。
- 「プリセット保存」では複数の設定に名前を付けて保存し、個別の編集・名前変更・読み込み・削除ができます。プリセットを編集しただけでは現在の設定は変わらず、読み込み後に反映されます。
- 検索履歴は直近 50 件を保存し、各部位のカラーコードと実測の ΔE を表示します。プリセットと検索履歴は別々に保存します。
- 表示言語は简体中文・繁體中文・English・日本語・한국어に対応します。ウィンドウはサイズ変更でき、色のカードは幅に合わせて 1～3 列に並びます。最前面のフローティングウィンドウはゲームのフォーカスを奪わず、クリック・ドラッグで操作できます。ゲームに操作を送る間は一時的に隠れ、その後再表示されます。
- データは通常、プログラムと同じ場所の `data` に保存します。書き込めない場合は `%LOCALAPPDATA%\MabinogiMobileColorStudio\data`、さらに失敗した場合は Windows の一時フォルダーを使います。
- 診断ログは直近 3 回分を保存し、実行中の記録は保護します。一時フォルダーのデータは Windows に削除される場合があります。

## 問題が起きた場合

実行中にゲームウィンドウの位置やサイズを変えた場合は、停止してから再開してください。複数の画面サイズと表示倍率でテストしていますが、すべての画面構成・混在 DPI・ゲームバージョンでの動作を確認したわけではありません。韓国版と日本版は引き続きテスト中です。

ゲームプロセスへのアクセスが拒否された場合は、ツールとゲームを同じ権限で実行してください。ゲームを管理者として実行している場合は、ツールを右クリックし「管理者として実行」で起動し直します。まずゲームの通常画面で再試行し、権限の確認が通ってから新しい染色を開始してください。ツールが自動で管理者権限を取得することはありません。

問題は今回のログを添えて [GitHub Issues](https://github.com/MinamiChiwa/mabinogi-mobile-color-studio/issues) で報告してください。報告のために染色アイテムを繰り返し消費する必要はありません。最終結果はゲーム内の現在のカラーコードで確認してください。

## 開発とテスト

Windows 10/11、Python 3.12 を使用します。製品のソースコードは `work/studio` にあります。

```powershell
python -m pip install -r requirements-build.txt
python work/studio/app.py
python scripts/run_tests.py
python scripts/run_tests.py --suite release
```

標準の高速テストは現在の製品仕様を確認します。リリース用テストでは、保存済みの実際の染色パレットを使った検索と復帰の確認を追加します。過去の実験や大規模な検索テストは `--suite research` または `--suite full` で実行できます。詳細は [TESTING.md](TESTING.md) を参照してください。結果には成功・スキップ・失敗・エラーと所要時間を表示します。テスト構成の違いで製品の検索能力やゲーム内の時間制限は変わりません。

ソースからの実行とパッケージ作成には Tesseract OCR と `eng.traineddata` が必要です。標準の場所は `C:/Program Files/Tesseract-OCR` で、`TESSERACT_HOME` で変更できます。OCR の言語は表示言語とは独立しています。

```powershell
python work/studio/build_release.py
```

出力先は `outputs/release/ColorStudio` です。個人の設定、セッション、スクリーンショットはリリースパッケージや Git に含めません。確認範囲は [VERIFICATION.md](work/studio/VERIFICATION.md)、変更内容は GitHub Releases を参照してください。

## 更新

更新機能を備えたバージョンでは、メイン画面から GitHub の更新を確認できます。**ダウンロードはユーザーが選び、インストールボタンをクリックすると更新します。** 差分ファイルを取得し、設定・プリセット・検索履歴を含む `data` 全体を保持します。更新署名を検証してから適用します。

GitHub に接続できない場合は、完全オフライン更新パッケージ **`UPDATE-ONLY-ColorStudio-0.4.3-win-x64.zip`** をツール内の更新機能から読み込めます。公式 0.4.2 からの更新に限り、増分パッケージ **`UPDATE-ONLY-ColorStudio-from-0.4.2-to-0.4.3-win-x64.zip`** も用意しています。更新専用パッケージは新規インストール用ではありません。詳しくは [更新ガイド](docs/automatic-updates.md) を参照してください。

更新機能のない旧バージョンからは、最初の 1 回だけ手動で更新してください。旧ツールを終了し、完全版のポータブルパッケージを新しいフォルダーに展開します。設定を引き継ぐ場合は、旧フォルダーの `data` を新しいフォルダーへコピーしてください。
